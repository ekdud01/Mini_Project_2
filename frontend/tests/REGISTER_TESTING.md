# 회원가입 검증

## 자동 테스트

`frontend`에서 실행한다.

```bash
npm run test:validation
npm run lint
npm run build
```

`validation.test.js`의 12개 테스트는 필수값, 이름·이메일 길이, 비밀번호 7·8·20·21자 경계와 ASCII 특수문자 32개, 공백·한글·제어문자 거부, 비밀번호 확인, 성별, 출생년도 경계·형식, 요청 본문 변환을 검사한다. 연도 경계 테스트는 2026년으로 고정한다.

## 서버 오류를 다시 확인하는 방법

Mock 모드의 브라우저 콘솔에서 아래 핸들러를 등록한 뒤 정상 형식의 회원가입 폼을 제출한다. 화면 검증을 통과해야 요청이 전송된다.

```js
devWorker.use(http.post('/api/members', () => HttpResponse.json({
  success: false,
  error: {
    code: 'VALIDATION_ERROR',
    fields: [
      { field: 'gender', message: '성별을 선택해주세요' },
      { field: 'birthYear', message: '출생년도는 올해까지만 입력할 수 있습니다' },
    ],
  },
}, { status: 400 })));
```

알 수 없는 필드는 `field: 'unknown'`을 추가하거나 그것만 남겨 확인한다. 500은 `status: 500`, `code: 'INTERNAL_SERVER_ERROR'` 응답으로, 네트워크 오류는 `HttpResponse.error()`로 확인한다. 응답 지연은 핸들러 안에서 `await delay(1800)` 후 응답 없이 반환하면 원래 Mock 핸들러가 처리한다.

확인 후 진행 중인 요청이 끝나면 다음 명령으로 원래 핸들러를 복원한다.

```js
devWorker.resetHandlers();
```
