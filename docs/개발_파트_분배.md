## 3. 프론트엔드 상세

프론트는 백엔드를 기다리지 않고 Mock 데이터(MSW)로 수요일까지 개발한 뒤, 목요일에 실제 API로 바꾼다. 사용법은 [`mock-data/README.md`](../mock-data/README.md)에 있다.

- [ ] axios 응답 인터셉터: 재발급 후 1회 재시도, 401 처리 (React 5.3)
- [ ] authStore `login()`·`logout()`, Header 로그인 상태별 메뉴·모바일 메뉴
- [ ] LoginPage·LoginForm (401·403 문구)
- [ ] RegisterPage (입력 검증 4.2, 서버 `fields` 표시, 409), `utils/validation.js`
- [ ] MyPage: ProfileCard, ExamHistoryTable(10건씩), ExamTrendChart(Recharts, 5.5), EmptyHistory, WithdrawDialog, memberStore
- [ ] 프론트 PR 검토·병합

### 서다영 — 검사 + 검사 결과

- [ ] surveyStore, resultStore(`pendingFirstAnswers` sessionStorage 유지), `utils/kdsq.js`
- [ ] SurveyPage(`type` P/C): SurveyHeader(안내 문구), ProgressBar, QuestionCard, AnswerOptions(원문 선택지), 이전·다음·제출 버튼
- [ ] 분기: 1차 0~3점 제출, 4점 이상 보관 후 `/surveys/c`, 1차 답변 없이 `/surveys/c` 진입 시 되돌리기, 422 처리

### 황지영 — 관리자 화면 (Thymeleaf)

## 5. 파트 간 약속

### 5.1 파일 주인

여러 사람이 동시에 수정하면 충돌하는 파일은 주인을 한 명으로 정한다. 다른 사람은 수정이 필요하면 주인에게 요청한다.

| 담당 | 파일 |
|---|---|
| 윤수연 | `build.gradle`, `application.properties`, `ErrorCode`, `ApiResponse`, `SecurityConfig` |
| 이주혁 | `data.sql` |
| 강찬식 | `package.json`, `vite.config.js`, `App.jsx`(라우터), `axiosInstance`, `authStore` |

### 5.2 임시 인증

JWT가 완성되기 전까지 로그인한 회원 id는 `SecurityUtil.currentMemberId()`로만 얻는다. JWT가 완성되면 이 함수의 내부만 교체하므로, 이를 사용하는 다른 코드는 고칠 필요가 없다.

### 5.3 관리자 화면 요청·Model 이름

| 요청 | 템플릿 | Model 이름 |
|---|---|---|
| GET `/admin/login` | `admin/login` | (파라미터 `error`, `logout`) |
| GET `/admin/dashboard` | `admin/dashboard` | `stats` (DashboardStatsDto) |
| GET `/admin/members?keyword=&page=` | `admin/members/list` | `members` (Page), `keyword` |
| GET `/admin/members/{id}` | `admin/members/detail` | `member`, `results` |
| GET·POST `/admin/members/{id}/edit` | `admin/members/edit` | `form`, `memberId` |
| POST `/admin/members/{id}/withdraw` | → 상세로 리다이렉트 | 플래시 `successMessage` / `errorMessage` |
| GET `/admin/results?examType=&riskLevels=&name=&from=&to=&page=` | `admin/results/list` | `results` (Page), `cond` (검색 조건) |
| GET `/admin/results/{id}` | `admin/results/detail` | `result` |
| POST `/admin/results/{id}/delete` | → 목록으로 리다이렉트 | 플래시 `successMessage` / `errorMessage` |

### 5.4 Git 규칙 (강사님 브랜치 전략)

- `develop`에서 `feature/be-…`, `feature/fe-…` 브랜치를 만들고, PR로 `develop`에 합친다. `main`은 10/5에만 병합한다.
- PR 검토·병합: 백엔드 윤수연, 프론트엔드 강찬식
- 커밋 메시지: `타입: 요약` (`feat`, `fix`, `docs`, `refactor`, `test`, `chore`)
- 기능 하나·파일 묶음 하나 단위로 하루에 여러 번 커밋한다. 개별 평가가 커밋 기록을 기준으로 하므로 하루치 작업을 모아 한 번에 올리지 않는다.
- 매일 저녁 디스코드에 **오늘 한 일 / 내일 할 일 / 막힌 점**을 한 줄씩 남긴다.
