# 화면 문구 작성 규칙

| 항목 | 내용 |
|------|------|
| 프로젝트 | MEMORY ATTACK — KDSQ 인지선별검사 플랫폼 |
| 작성일 | 2026-09-30 |
| 작성자 | 윤수연 |
| 기준 문서 | UI 화면 설계서 2.4 '메시지 문구 작성 규칙', React 컴포넌트 설계서 5.3 (오류 코드별 화면 문구) |

화면에 보이는 문구를 코드에 쓸 때 지키는 규칙과, 문구가 코드 어디에 있는지를 정리한 문서다.
규칙 자체는 UI 설계서 2.4가 기준이고, 이 문서는 **코드에 적용하는 방법**을 다룬다. 두 문서가 다르면 설계서를 따르고 이 문서를 고친다.

---

## 1. 규칙

| 규칙 | 내용 | 올바른 예 | 틀린 예 |
|------|------|-----------|---------|
| 끝 마침표 없음 | 화면에 보이는 모든 문구는 마지막에 마침표를 찍지 않는다 | 이메일을 입력해주세요 | 이메일을 입력해주세요. |
| 한 줄에 두 문장 | 문장 사이에만 마침표를 둔다 | 네트워크 오류가 발생했습니다. 잠시 후 다시 시도해주세요 | 네트워크 오류가 발생했습니다. 잠시 후 다시 시도해주세요. |
| 줄을 나눈 문장 | `<br>`, `\n`, 별도 태그로 나눈 줄은 **모든 줄 끝**에 마침표를 찍지 않는다 | 1차 검사에서 종료되어 … 제공되지 않습니다 `\n`6개월\~1년 후 다시 검사해 보시길 권장합니다 | …제공되지 않습니다. `\n`…권장합니다. |
| 띄어쓰기 | "\~해주세요"는 붙여 쓴다 | 입력해주세요, 시도해주세요 | 입력해 주세요 |
| 같은 상황은 같은 문구 | 서버 `ErrorCode` · 검증 문구와 화면 문구를 글자 그대로 맞춘다. 관리자 폼도 같은 문구 | 이미 사용 중인 이메일입니다 | 이미 가입된 이메일입니다 |
| 설계서 문구 그대로 | UI 설계서 3 · 4장, React 설계서 5.3에 적힌 문구는 바꾸지 않고 쓴다 | — | 비슷한 뜻으로 바꿔 쓰기 |

### 1.1 적용 대상

입력칸 아래 오류, API 응답 `message`, Alert · 토스트, 관리자 플래시 메시지, 에러 페이지(403 · 404 · 500), 빈 목록 · 안내 문구, 확인 창(제목 · 설명), placeholder, 버튼 아래 보조 설명, **KDSQ 문항과 설문 안내문**까지 모두 적용한다.

> KDSQ 문항 · 설문 안내문은 처음에 원문 표기 예외였지만, 9/30 팀 결정으로 마침표를 없앴다 (PR #38). 문구 내용은 원문 그대로 두고 끝 마침표만 뺀다.

### 1.2 적용하지 않는 곳

| 대상 | 예 |
|------|----|
| 코드 주석 · JavaDoc | `// 토큰을 지운다.` |
| 개발자용 로그 · 콘솔 | `log.info(...)`, `console.info(...)` |
| 화면에 그대로 나가지 않는 예외 메시지 | `new IllegalArgumentException("…")`, `new Error("…")` (화면에는 500 · 공통 문구로 바뀌어 보임) |
| 문서(md) 본문 | 설계서 · README 설명 문장 |

### 1.3 용어

| 화면 | 쓰는 말 | 쓰지 않는 말 |
|------|---------|--------------|
| 사용자 화면 (본인) | 탈퇴, 회원 탈퇴가 완료되었습니다 | 비활성화 |
| 관리자 화면 | 비활성, 비활성화, 활성화, 비활성화되었습니다 | 탈퇴 처리 |
| 공통 | 서비스명 MEMORY ATTACK | KDSQ 플랫폼 등 다른 이름 |
| 판정 | 정상 · 주의 · 위험 | 경계, 고위험 |

## 2. 문구가 있는 곳

문구를 추가하거나 고칠 때 아래 위치를 같이 확인한다. 같은 문구가 서버와 화면 두 곳 이상에 있으면 **모두** 고친다.

### 2.1 백엔드

| 위치 | 파일 | 화면에 나오는 곳 |
|------|------|------------------|
| API 오류 문구 | `global/exception/ErrorCode.java` | API 응답 `error.message` → 사용자 화면 알림 |
| 입력 검증 문구 | `*/dto/*Request.java`, `admin/dto/*Form.java`의 `message = "…"` | 입력칸 아래 오류 (`error.fields`, 관리자 `th:errors`) |
| API 성공 문구 | 각 `*Controller.java`의 `ApiResponse.ok(…, "…")` | 사용자 화면 알림 |
| 관리자 플래시 | `admin/*Controller.java`의 `addFlashAttribute("successMessage" / "errorMessage", "…")` | 관리자 화면 상단 알림 |
| 관리자 화면 글자 | `templates/admin/**/*.html`, `templates/fragments/*.html` | 제목, 빈 목록, 버튼, 안내 |
| 확인 창 | 템플릿의 `data-confirm-title`, `data-confirm` 속성 (`static/js/admin.js`가 표시) | 비활성화 · 활성화 · 삭제 확인 |
| 에러 페이지 | `templates/error/403.html`, `404.html`, `500.html` | 오류 화면 |
| 문항 · 안내 · 솔루션 | `resources/data.sql` | 검사 화면, 결과 화면 솔루션 |

> `data.sql`은 `INSERT IGNORE`라 이미 만들어진 DB에는 다시 들어가지 않는다. 문구를 바꾸면 PR 설명에 **UPDATE SQL**을 같이 적는다.

### 2.2 프론트엔드

| 위치 | 파일 | 화면에 나오는 곳 |
|------|------|------------------|
| 입력 검증 문구 | `src/utils/validation.js` | 입력칸 아래 오류 (서버 검증 문구와 같아야 함) |
| 오류 코드별 문구 | `src/utils/apiError.js`, 각 페이지의 `messages` 객체 | 알림 (React 설계서 5.3 표 기준) |
| 네트워크 · 재발급 실패 | `src/api/axiosInstance.js`, `src/utils/apiError.js` | "다시 로그인해주세요", 네트워크 오류 |
| 화면 글자 | `src/pages/**`, `src/components/**`의 JSX | 제목, 안내, 빈 상태, 확인 창 |
| Mock 응답 | `mock-data/responses/**/*.json`, `mock-data/data/*.json`, `mock-data/msw/handlers.js` | Mock 모드 화면 (실서버 문구와 같아야 함) |

### 2.3 테스트

문구를 바꾸면 문구를 그대로 비교하는 테스트도 같이 고친다.

| 테스트 | 확인하는 문구 |
|--------|---------------|
| `backend/src/test/.../SignupRequestValidationTest.java` | 회원가입 검증 문구 |
| `backend/src/test/.../AdminMemberServiceTest.java` 등 | 예외 코드 (문구 대신 `ErrorCode`로 비교) |
| `frontend/tests/auth.test.js` | 로그인 · 재발급 · 오류 문구 |
| `frontend/tests/validation.test.js` | 프론트 입력 검증 문구 |

## 3. 문구를 추가 · 수정하는 순서

1. UI 설계서 3 · 4장, React 설계서 5.3에 같은 상황의 문구가 있는지 찾는다. 있으면 그대로 쓴다
2. 서버가 보내는 문구면 `ErrorCode` · DTO 검증 문구를 먼저 정하고, 화면은 그 문구를 그대로 쓴다
3. 2장 표의 위치에서 같은 문구가 있는 곳을 모두 고친다 (Mock JSON 포함)
4. 4장 확인 명령을 실행한다
5. 문구를 비교하는 테스트를 고치고 실행한다 (`./gradlew cleanTest test`, `npm run test:auth`, `npm run test:validation`)
6. 설계서에 없는 새 문구면 PR 설명에 적어서 설계서 담당이 반영하게 한다

## 4. 확인 명령

PR 올리기 전에 프로젝트 루트(Git Bash)에서 실행한다. "\~다." / "\~요." / "\~오."로 끝나는 문자열 · 태그 글자(괄호 안 문장 포함)를 찾고, 주석 줄은 뺀다.

```bash
LC_ALL=C grep -rnE "(다|요|오)\.([\"'\`<|)]|[[:space:]]*$)" \
  backend/src/main frontend/src mock-data \
  --include=*.java --include=*.html --include=*.sql \
  --include=*.js --include=*.jsx --include=*.json \
  | LC_ALL=C grep -vE '^[^:]+:[0-9]+:[[:space:]]*(//|\*|/\*|--|\{/\*)'
```

- 결과가 나오면 1.2 '적용하지 않는 곳'(줄 끝 주석, `new Error`, `console`, `IllegalArgumentException`)인지 확인하고, 화면에 보이는 문구면 고친다
- 한 줄에 두 문장인 경우 안쪽 마침표는 정상이라 이 명령에 걸리지 않는다
- "해 주세요" 띄어쓰기 확인:

```bash
grep -rn "해 주세요" backend/src/main frontend/src mock-data
```

> 설문 안내문의 "표시해 주십시오"처럼 KDSQ 원문 표현은 내용을 바꾸지 않으므로 그대로 둔다.

## 5. PR 확인 항목

- [ ] 새로 쓰거나 고친 문구 끝에 마침표가 없다
- [ ] "\~해주세요"를 붙여 썼다
- [ ] 서버와 화면(Mock 포함)의 같은 상황 문구가 글자까지 같다
- [ ] 사용자 화면은 "탈퇴", 관리자 화면은 "비활성화"를 썼다
- [ ] 4장 확인 명령 결과에 화면 문구가 없다
- [ ] 문구를 비교하는 테스트를 고치고 통과했다
- [ ] `data.sql` 문구를 바꿨다면 PR 설명에 UPDATE SQL을 적었다
