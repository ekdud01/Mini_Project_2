# 공통 디자인 프롬프트 — 사용자 화면 (React)

> 사용법: 사용자 화면(로그인·회원가입·마이페이지 등)을 AI로 만들거나 고칠 때 아래 블록을 먼저 붙여 넣고, 이어서 화면별 요구사항을 붙인다.
> 기준: UI 화면설계서 2·3·8장, UI 2.4 메시지 문구 작성 규칙, 현재 develop 코드(`authStore`, `utils/apiError.js`, `components/ui/*`, `index.css`)

```text
너는 "MEMORY ATTACK · KDSQ 인지선별검사 플랫폼"(팀 REMEMNE)의 React 화면을 만든다.
주 사용자는 인지 저하가 걱정되는 고령층과 보호자다. 크고, 읽기 쉽고, 누르기 쉬운 화면이 최우선이다.
분위기: 흰 카드 + 연한 회색 배경 + 파란 포인트. 차분하고 신뢰감 있는 의료 서비스 톤. 장식·그라데이션·과한 그림자 금지.

## 기술 스택 (반드시 이 안에서만)
- React 19 + Vite, JavaScript(JSX) + PropTypes (TypeScript 아님)
- Tailwind CSS v4 (index.css 토큰), shadcn/ui (radix-ui 기반), lucide-react 아이콘
- 상태: Zustand, 라우팅: react-router-dom v7
- 경로 별칭 @/ = src/, 클래스 병합은 cn() (@/lib/utils)
- 있는 shadcn 컴포넌트: alert, badge, button, card, chart, dialog, input, label, progress, radio-group, table
  (그 외 컴포넌트는 새로 설치하지 말 것)
- 페이지 전용 컴포넌트는 src/pages/<Page>/components/ 에 만든다.

## 이미 있는 코드 (새로 만들지 말고 그대로 사용)
- useAuthStore (@/store/authStore)
  · accessToken, email, logoutReason
  · login(email, password): 실패 시 axios 오류를 그대로 throw
  · logout(): 서버 실패해도 finally 에서 로컬 인증 정보 삭제 (reject 하지 않음)
  · clearLogoutReason(): logoutReason 을 한 번 표시한 뒤 호출
  · 토큰 재발급 실패 시 axiosInstance 가 clear({ reason: '다시 로그인해주세요' }) 로 logoutReason 을 채운다.
- @/utils/apiError
  · getErrorCode(error) → 'INVALID_CREDENTIALS' 등 서버 오류 코드
  · getFieldErrors(error) → { email: '...', birthYear: '...' } (400 VALIDATION_ERROR 의 fields)
  · getErrorMessage(error, { CODE: '문구' }, fallback) → 네트워크 오류면 네트워크 문구, 코드가 맵에 없으면 fallback
- ProtectedRoute: accessToken 이 없으면 /login 으로 보낸다.
- LoadingSpinner (@/components/common/LoadingSpinner)

## 디자인 토큰 (index.css 기준, 새 색을 만들지 말 것)
- primary #3b82f6 (bg-primary, text-primary, bg-primary/5, bg-primary/10, border-primary/30)
- destructive #ef4444 (오류), success #22c55e (완료 안내)
- foreground #1f2937, muted-foreground #64748b, border #e2e8f0, 보조 배경 slate-50 / slate-100
- 카드 rounded-2xl, 내부 박스 rounded-xl, 입력칸·안내 박스 rounded-lg

## 타이포그래피 (모바일에서도 줄이지 않음)
- 카드 제목 text-2xl font-bold, 제목 위 보조 문구 text-sm font-semibold text-primary
- 본문·입력값 16px(text-base) 이상. 라벨 text-base font-semibold.
- 안내·오류 문구 최소 text-sm(14px). text-xs 는 쓰지 않는다 (고령층 가독성).
  예외: 공통 Footer 의 면책 문구는 현재 디자인(text-xs)을 유지한다.
- 한국어 문장이 단어 중간에서 끊기지 않도록 제목·안내 문구에 break-keep.

## 공통 패턴
- 페이지 배경: 연한 회색(bg-slate-50). UserLayout 의 <main> 안에서 가운데 정렬 카드로 보여준다.
- 인증 카드: `mx-auto w-full max-w-md rounded-2xl border bg-white p-6 shadow-sm md:p-10` + 내부 `space-y-6`
- 입력칸: shadcn <Input> 기본값이 h-9 / md:text-sm 이므로 반드시 덮어쓴다.
  className="h-12 rounded-lg bg-slate-50 px-4 text-base md:text-base"
  오류 시 aria-invalid="true" (shadcn 이 테두리를 destructive 로 바꿔준다).
- 입력 그룹: `space-y-2` 안에 <Label htmlFor> → <Input> → 안내/오류 문구
- 필수 표시: 라벨 뒤 <span class="text-destructive" aria-hidden="true">*</span> + 입력에 aria-required="true"
- 필드 오류 문구: `<p id="{field}-error" role="alert" class="text-sm font-medium text-destructive">`
  입력에 aria-describedby="{field}-error" (안내 문구가 있으면 "{field}-hint {field}-error" 로 둘 다 연결)
- 폼 상단 알림(서버 오류·재로그인 안내·가입 완료):
  · 오류: <Alert variant="destructive"> + lucide AlertCircle
  · 안내: <Alert className="border-primary/30 bg-primary/5 text-primary"> + lucide Info
  · 완료: <Alert className="border-success/40 bg-success/10 text-foreground"> + lucide CheckCircle2 (아이콘만 text-success)
  · 모두 role="alert" (오류) / role="status" (안내·완료)
- 주요 버튼: <Button type="submit" size="lg" className="h-14 w-full text-lg font-bold">
  요청 중: disabled + <Loader2 className="animate-spin" aria-hidden /> + "~ 중..." 문구 + aria-busy="true"
- 보조 링크: text-base font-semibold text-primary hover:underline, 터치 영역 확보를 위해 inline-flex min-h-12 items-center
- 비밀번호 보기 토글: 입력칸 오른쪽 안쪽에 <button type="button">, lucide Eye / EyeOff,
  aria-label="비밀번호 보기" / "비밀번호 숨기기", aria-pressed, 크기 size-10, 입력칸은 pr-12.

## 반응형 · 접근성 (WCAG 2.1 AA)
- 모바일 우선. 375px 에서 가로 스크롤 없음. 카드는 모바일에서 좌우 16px 여백만 두고 전체 폭.
- 누르는 요소 높이 최소 48px, 간격 최소 8px.
- <form noValidate> 로 브라우저 기본 말풍선을 끄고 직접 검증한다.
- 제출 실패 시 첫 번째 오류 입력칸으로 focus().
- 포커스 링을 제거하지 않는다. Tab 순서 = 화면 순서.
- 화면마다 document.title: "로그인 - MEMORY ATTACK", "회원가입 - MEMORY ATTACK"

## 문구 작성 규칙 (UI 2.4)
- 톤: 존댓말, "~해주세요" 로 끝나는 짧은 문장.
- 화면에 보이는 모든 문구는 끝에 마침표를 찍지 않는다
  (입력칸 아래 오류, 알림, 빈 목록 안내, 확인창, placeholder, 안내 문구).
- 한 줄에 문장이 둘이면 문장 사이에만 마침표: "네트워크 오류가 발생했습니다. 잠시 후 다시 시도해주세요"
- 줄을 나눈 경우(<br>, 별도 태그)도 각 줄 끝에 찍지 않는다.
- 예외: KDSQ 문항·설문 안내 원문, 개발자용 메시지(console, new Error(...)).
- 설계서(UI 3장, React 5.3)에 적힌 문구는 글자 그대로 사용한다.
```
