# 통합 테스트 체크리스트

| 항목 | 내용 |
|------|------|
| 프로젝트 | MEMORY ATTACK — KDSQ 인지선별검사 플랫폼 |
| 팀 | REMEMNE (리멤느) |
| 작성일 | 2026-09-30 |
| 작성자 | 윤수연 |
| 대상 브랜치 | `develop` (관리자 검사 결과 관리 · 마이페이지 머지 후) |
| 참고 문서 | UI 설계서, REST API 설계서, Entity 설계서, React 컴포넌트 설계서 |

프론트(React) · 백엔드(Spring Boot) · DB(MariaDB)를 실제로 연결한 상태에서 사용자 화면과 관리자 화면의 전체 흐름을 확인한다.
단위 테스트로 확인하기 어려운 **화면 이동, 토큰 처리, 두 화면 사이의 데이터 연동**을 중심으로 본다.

- 결과 칸은 `✅ 통과` / `❌ 실패` / `➖ 해당 없음`으로 적고, 실패하면 6장 기록표에 내용을 남긴다
- 문구는 UI 설계서 2.4 규칙(화면 문구 끝 마침표 없음)을 같이 확인한다
- 대시보드 숫자는 테스트 중에 계속 바뀌므로 고정값 대신 **증가·감소 여부**로 확인한다

## 3. 사용자 ↔ 관리자 연동

두 브라우저(또는 일반 창 + 시크릿 창)를 열어 사용자와 관리자를 동시에 로그인해 두고 확인한다.

| ID | 순서 | 기대 결과 | 결과 |
|----|------|-----------|------|
| I-01 | 사용자가 가입 | 관리자 회원 목록 맨 위에 새 회원, 대시보드 전체 회원 +1 | ✅ 통과 |
| I-02 | 사용자가 1차에서 정상으로 끝남 | 관리자 결과 목록에 "1차만" 결과 추가, 대시보드 전체 검사 +1 · 정상 +1 | ✅ 통과 |
| I-03 | 사용자가 2차까지 위험으로 끝남 | 대시보드 위험 건수 +1, 최근 위험 판정 목록 맨 위 | ✅ 통과 |
| I-04 | 관리자 회원 상세 | I-02 · I-03 결과가 회원 검사 이력에 보임 | ✅ 통과 |
| I-05 | 관리자가 I-03 결과 삭제 | 사용자 마이페이지 이력 · 그래프에서 사라짐, 결과 주소는 "검사 결과를 찾을 수 없습니다", 대시보드 숫자 감소 | ✅ 통과 |
| I-06 | 관리자가 회원 이름 · 출생년도 수정 | 사용자 마이페이지 새로고침 시 바뀐 값 | ✅ 통과 |
| I-07 | 관리자가 사용자 비활성화 | 사용자 로그인 시 "이용할 수 없는 계정입니다", 대시보드 탈퇴 +1 | ✅ 통과 |
| I-08 | 비활성화된 사용자가 이미 로그인한 창에서 새로고침 | 재발급 실패 시 로그인 화면 (access token 만료 전 조회는 될 수 있음, 아래 참고) | ✅ 통과 |
| I-09 | 관리자가 다시 활성화 | 사용자 정상 로그인, 이전 검사 이력 그대로 | ✅ 통과 |
| I-10 | 사용자가 마이페이지에서 탈퇴 | 관리자 회원 목록 상태 비활성, 결과는 관리자 목록에 남음 | ✅ 통과 |

> 참고: 탈퇴 · 비활성화 직후에도 이미 발급된 access token은 최대 1시간 유효하다. 이 동안 결과 조회는 될 수 있고, 검사 제출 · 내 정보 조회는 404, 재발급은 실패한다. 설계상 허용 범위로 보고, 결과가 다르면 기록표에 남긴다.
