## 1. 화면 목록 개요

### 1.1 사용자(User) 화면 목록

| 화면 ID | 페이지명 | URL | 인증 | 주요 기능 | 필요한 API |
| --- | --- | --- | --- | --- | --- |
| SCR-01 | 로그인   | `/login` | X | 이메일/비밀번호 입력, JWT 발급, 회원가입 이동 | `POST /api/auth/login` |
| SCR-02 | 회원가입  | `/register` | X  | 회원정보(이름/이메일/비밀번호/성별/출생년도) 입력 및 등록 | `POST /api/members` |
| SCR-03 | 검사 메인(1차) | `/surveys/p` | O  | KDSQ-P 검사. 0~3점이면 결과 저장, 4점 이상이면 저장 없이 2차로 | `GET /api/surveys/{surveyId}/questions` `POST /api/results` |
| SCR-04 | 상세 검사(2차) | `/surveys/c` | O  | KDSQ-C 검사. 1·2차 답변을 함께 제출해 결과 1건 저장 | `GET /api/surveys/{surveyId}/questions` `POST /api/results` |
| SCR-05 | 검사 결과 | `/results/:resultId` | O  | 결과/위험도/솔루션(주의·위험 공통) | `GET /api/results/:resultId` |
| SCR-06 | 마이페이지 | `/mypage`         | O  | 회원정보 조회, 검사 이력, 회원 탈퇴  | `GET /api/members/me` `GET /api/members/me/results` `DELETE /api/members/me` |
| (공통) | 로그아웃 | — | O | 토큰 폐기 후 `/login` 이동 | `POST /api/auth/logout` |

### 1.3 권한별 접근 정책

| 권한 | 접근 범위 | 비고 |
|---|---|---|
| 공개 | 로그인, 회원가입, 관리자 로그인 | 검사 및 마이페이지 접근 불가 |
| 사용자 | 공개 화면 + 검사 + 결과 + 마이페이지 | 회원정보는 조회 전용(수정은 관리자만), 본인 탈퇴 가능 |
| 관리자 | 관리자 로그인 후 관리자 전체 화면 | 회원정보·검사 결과 관리 가능 |
| 개발자(유지보수) | 화면 설계 범위 외 | 운영 데이터 조회 권한 없음 |

### 1.4 핵심 검사 흐름

```text
회원가입
   ↓
로그인
   ↓
KDSQ-P (1차) 5문항
   ↓
1차 합계 확인 (10점 만점, 화면 이동 판단용)
   ├── 0~3점 → POST /api/results → 서버 채점·정상 판정, 결과 1건 저장 → 결과 화면 → 종료
   │
   └── 4~10점 → 저장하지 않고 KDSQ-C (2차) 진행 (1차 답변은 화면에 보관)
                    ↓
             15문항 응답
                    ↓
      POST /api/results (1차 5문항 + 2차 15문항 답변)
                    ↓
      서버: 1차 재채점·검증, memoryScore + otherScore + adlScore 산출 (각 10점 만점)
            totalScore = memory + other + adl (30점 만점, 저장하지 않고 응답에 포함)
            firstScore + 영역별 점수를 결과 1건으로 저장
                    ↓
             ┌──────┴──────┐
             ↓             ↓
           0~5점          6~30점
            주의           위험
             └──────┬──────┘
                    ↓
             결과 화면
        (관리·추가 검진 안내 포함)
                    ↓
                 마이페이지
```

> 판정 기준은 문서 전체에서 **KDSQ-P 0\~3 정상 / 4\~10 2차 대상**, **KDSQ-C 0\~5 주의 / 6\~30 위험**으로 통일한다.
>
> **저장 정책**: 검사 1회당 결과는 1건만 저장한다. 2차 대상자가 KDSQ-C를 완료하지 않고 이탈하면 결과를 저장하지 않는다. 최종 채점·판정은 서버가 수행하며, 화면의 1차 합계는 2차 진행 여부 판단에만 사용한다.

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Header                                                                   │
│ [KDSQ 관리자]   [대시보드][회원 관리][검사 결과]   ○○○ 관리자님   [로그아웃]  │
```

> **플래시 메시지**: 저장/수정/탈퇴 처리/삭제 등 처리 후 결과를 알려주는 공통 영역이며, 성공(초록)·실패(빨강) 두 종류만 사용한다.

## 2.5 관리자 템플릿 구조 (Thymeleaf)

관리자 화면은 Thymeleaf Layout Dialect로 공통 레이아웃을 한 번만 만들고, 각 화면은 본문(`content`)만 작성한다. 헤더·사이드바·브레드크럼·플래시 메시지·페이지네이션은 프래그먼트로 분리해 재사용한다.

```text
src/main/resources/
├── templates/
│   ├── layout/
│   │   └── admin-layout.html       # 공통 레이아웃 (header + sidebar + content + footer)
│   ├── fragments/
│   │   ├── header.html             # 로고, 상단 메뉴, 관리자 이름, 로그아웃
│   │   ├── sidebar.html            # 대시보드/회원 관리/검사 결과 메뉴 (현재 메뉴 강조)
│   │   ├── breadcrumb.html         # 브레드크럼 (2.3 경로)
│   │   ├── flash.html              # 성공/실패 플래시 메시지
│   │   ├── pagination.html         # 목록 공통 페이지네이션 (Page 객체 사용)
│   │   └── footer.html
│   ├── admin/
│   │   ├── login.html              # ADM-01 (레이아웃 미사용)
│   │   ├── dashboard.html          # ADM-02
│   │   ├── members/
│   │   │   ├── list.html           # ADM-03
│   │   │   ├── detail.html         # ADM-04
│   │   │   └── edit.html           # ADM-04-1
│   │   └── results/
│   │       ├── list.html           # ADM-05
│   │       └── detail.html         # ADM-06
│   └── error/
│       ├── 403.html                # 권한 없음
│       ├── 404.html                # 없는 페이지·없는 회원/결과
│       └── 500.html                # 서버 오류
└── static/
    ├── css/admin.css
    └── js/admin.js                 # 삭제·탈퇴 확인창, 플래시 메시지 자동 닫기
```

**레이아웃 상속 예시**

```html
<!-- layout/admin-layout.html -->
<html xmlns:th="http://www.thymeleaf.org"
      xmlns:layout="http://www.ultraq.net.nz/thymeleaf/layout"
      xmlns:sec="http://www.thymeleaf.org/extras/spring-security" lang="ko">
<head><title layout:title-pattern="$CONTENT_TITLE | KDSQ 관리자">KDSQ 관리자</title></head>
<body>
  <header th:replace="~{fragments/header :: header}"></header>
  <aside th:replace="~{fragments/sidebar :: sidebar}"></aside>
  <main>
    <nav th:replace="~{fragments/breadcrumb :: breadcrumb}"></nav>
    <div th:replace="~{fragments/flash :: flash}"></div>
    <section layout:fragment="content"></section>   <!-- 각 화면 본문 -->
  </main>
  <footer th:replace="~{fragments/footer :: footer}"></footer>
</body>
</html>

<!-- admin/members/list.html -->
<html layout:decorate="~{layout/admin-layout}">
<head><title>회원 관리</title></head>
<section layout:fragment="content">
  <form th:action="@{/admin/members}" method="get"> ... </form>
  <table> <tr th:each="m : ${members.content}"> ... </tr> </table>
  <div th:replace="~{fragments/pagination :: pagination(${members}, '/admin/members')}"></div>
</section>
</html>
```

**폼 처리 규칙**

| 항목 | 규칙 |
|---|---|
| 데이터 바인딩 | 수정 폼은 `th:object="${form}"` + `th:field`로 바인딩한다 |
| 검증 오류 | 컨트롤러에서 `@Valid` + `BindingResult`로 검증하고, 입력칸 아래에 `th:errors`로 오류 문구를 표시한다 |
| CSRF | 모든 POST 폼(로그인, 수정, 탈퇴 처리, 삭제)은 `th:action`을 사용해 CSRF 토큰 hidden 필드가 자동으로 들어가게 한다 |
| 상태 변경 | 탈퇴 처리·삭제는 GET 링크가 아니라 POST 폼 + 확인창으로 처리한다 |
| 처리 후 이동 | POST 처리 후에는 PRG(Post-Redirect-Get) 패턴으로 리다이렉트하고 `RedirectAttributes`로 플래시 메시지를 전달한다 |

**에러 페이지**

| 상황 | 페이지 | 표시 내용 |
|---|---|---|
| ADMIN이 아닌 계정이 관리자 기능 접근 | `error/403.html` | "접근 권한이 없습니다." + 관리자 로그인 이동 |
| 없는 URL, 없는 회원·결과 ID | `error/404.html` | "요청한 페이지를 찾을 수 없습니다." + 대시보드 이동 |
| 처리 중 예기치 않은 오류 | `error/500.html` | "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요." |

> Spring Boot는 `templates/error/{상태코드}.html`을 자동으로 사용한다. 목록·상세 화면의 "조회 실패" 상태(4장)는 화면 안의 오류 메시지로 표시하고, 권한·없는 리소스·서버 오류는 위 에러 페이지로 처리한다.

# 3. 사용자 화면별 상세 설계

## 3.1 SCR-01 — 로그인 화면

```text
  POST /api/results   저장하지 않음
  {surveyId, answers}  1차 답변을 pendingFirstAnswers에 보관
          ↓             ↓
  서버 채점·정상 판정   KDSQ-C 안내
          ↓             ↓
  /results/:resultId   /surveys/c
```

### 3.3.6 상태 및 데이터 정의 

| 상태 변수             | 타입                    | 설명                   |
| ----------------- | --------------------- | -------------------- |
| `questions`       | `Question[]`          | KDSQ-P 5개 검사 문항 목록   |
| `currentIndex`    | `number`              | 현재 문항의 인덱스     |
| `answers`         | `Answer[]` / `Record` | 각 문항에 대해 사용자가 선택한 답변 |
| `loading`         | `boolean`             | 검사 문항 조회 중 여부 (`surveyStore.loading`) |
| `submitting`      | `boolean`             | 검사 결과 제출 중 여부        |
| `surveyId`        | `number`              | KDSQ-P 설문 ID (`GET /api/surveys`로 확인) |
| `pendingFirstAnswers` | `Answer[]`        | 4점 이상일 때 2차 제출까지 보관하는 1차 답변 (resultStore, sessionStorage 유지) |

> 1차 합계는 상태로 저장하지 않고 `answers`에서 계산하며, 2차 진행 여부 판단에만 사용한다. 최종 채점·판정은 서버가 수행한다.

### 3.4.4 문항 영역 및 점수 구성

KDSQ-C는 총 15문항으로 구성되며, 문항 번호에 따라 3개 영역으로 구분하여 점수를 집계한다.

| 영역                    | 문항    | 점수 필드         | 설명                   |
| --------------------- | ----- | ------------- | -------------------- |
| **기억력 (KDSQ-M)**      | 1~5   | `memoryScore` | 기억력 관련 문항 점수 합계      |
| **기타 인지기능 (KDSQ-O)**  | 6~10  | `otherScore`  | 기타 인지기능 관련 문항 점수 합계  |
| **일상생활수행능력 (KDSQ-A)** | 11~15 | `adlScore`    | 일상생활수행능력 관련 문항 점수 합계 |
| **전체**                | 1~15  | `totalScore`  | 3개 영역 점수의 합계 (저장하지 않고 서버가 계산해 응답) |

```text
memoryScore = Q1 + Q2 + Q3 + Q4 + Q5
otherScore  = Q6 + Q7 + Q8 + Q9 + Q10
adlScore    = Q11 + Q12 + Q13 + Q14 + Q15

totalScore = memoryScore + otherScore + adlScore
```

> 문항별 `answers`는 저장하지 않는다. 위 계산은 서버(ScoringService)가 수행하며, `firstScore`, `memoryScore`, `otherScore`, `adlScore`를 결과 1건에 저장한다. `totalScore`는 서버가 계산하여 응답에 포함한다.

### 3.6.5 상태 및 데이터 정의 

| 상태 변수         | 타입             | 설명                |
| ------------- | -------------- | ----------------- |
| `me`          | `Member`       | 로그인한 사용자의 회원정보 (`memberStore.me`) |
| `history`     | `SurveyResult[]` | 사용자의 과거 검사 결과 목록 (`resultStore.history`) |
| `isLoading`   | `boolean`      | 데이터 조회 중 여부 (`MyPage.isLoading`) |
| `errorMessage` | `string`      | 조회 오류 메시지 (`MyPage.errorMessage`) |

**회원정보**
```text
me
├── name
├── email
├── gender
└── birthYear
```

**검사 이력**
```text
history[]
├── id
├── examType      (결과가 참조하는 설문의 검사 유형)
├── firstScore
├── totalScore    (KDSQ-P로 끝난 결과는 null)
├── riskLevel
└── createdAt
```

**KDSQ-C 영역별 데이터**
```text
KDSQ-C
├── memoryScore
├── otherScore
├── adlScore
└── totalScore
```

> KDSQ-P로 끝난 결과는 `memoryScore` / `otherScore` / `adlScore` / `totalScore`가 null이며, 화면에는 "-"로 표시한다.

> 문항별 answers는 마이페이지에서 조회하거나 표시하지 않는다.

### 3.6.6 검사 이력 표시 기준

| 항목     | 내용               |
| ------ | ---------------- |
| **날짜** | 검사 완료일           |
| **검사** | KDSQ-P 또는 KDSQ-C |
| **총점** | KDSQ-P로 끝난 결과는 `firstScore`(10점 만점), KDSQ-C까지 수행한 결과는 `totalScore`(30점 만점) |
| **결과** | 검사 점수에 따른 결과 유형  |

**결과 유형**

| 검사     |   점수 | 표시 결과       |
| ------ | ---: | ----------- |
| KDSQ-P |  0~3 | 정상          |
| KDSQ-C |  0~5 | 주의          |
| KDSQ-C | 6~30 | 위험      |

> KDSQ-P 4~10점(2차 대상)은 2차까지 완료해야 저장되므로 이력에 나타나지 않는다.

### 3.6.7 표시 규칙

| 원본 값 | 화면 표기 |
| :--- | :--- |
| `gender: MALE / FEMALE` | 남성 / 여성 |
| `birthYear: 1960` | 1960 (만 66세) — 현재연도 − 출생년도 |
| `examType: KDSQ_P / KDSQ_C` | KDSQ-P / KDSQ-C |
| `riskLevel: Normal` | `정상` 배지 |
| `riskLevel: Borderline` | `주의` 배지 |
| `riskLevel: HighRisk` | `위험` 배지 |
| `createdAt` | `YYYY-MM-DD` (시각 생략) |
| 추이 그래프 점수 | KDSQ-C까지 수행한 결과는 `totalScore`(30점 만점), KDSQ-P로 끝난 결과는 `firstScore`(10점 만점). y축은 0~30으로 고정하고, 점에 마우스를 올리면 검사 종류·점수·판정 표시 |
| 영역별 점수·총점 `null` | `-` |

### 3.6.8 사용자 인터랙션 흐름

```text
[마이페이지 클릭]
   ↓
[ProtectedRoute 통과 확인 (토큰 유무)]
   ↓
[MyPage 마운트] → isLoading = true
   ↓
[GET /api/members/me]        ─┐
[GET /api/members/me/results?size=100] ─┴─ 병렬 호출 (Promise.all)
   (추이 그래프는 전체 이력으로 그리고, 이력 표는 화면에서 페이지를 나눔)
   → [두 요청 모두 성공]
          → [응답의 totalScore / firstScore를 그대로 표시 (프론트 계산 없음)]
                 ↓
         [history.length === 0 ?]
              → [Yes] → [ProfileCard + 빈 상태 안내 (그래프 미렌더)]
              → [No]  → [ProfileCard + ExamHistoryTable + ExamTrendChart]

   → [401 ACCESS_TOKEN_EXPIRED] → [아래 토큰 만료·재발급 플로우]

   → [그 외 오류] → [Alert + 다시 시도 버튼]
```

**토큰 만료 / 재발급**

```text
[API 응답 401 수신 (axios 응답 인터셉터)]
   ↓
[error.code 확인]
   │
   ├── [ACCESS_TOKEN_EXPIRED + 리프레시 토큰 보유]
   │        → [POST /api/auth/reissue]
   │            ├── [성공] → [새 액세스 토큰 저장] → [실패했던 요청 1회 재시도]
   │            └── [INVALID_REFRESH_TOKEN] → [authStore.logout()] → [/login ("다시 로그인해주세요.")]
   │                 (재발급 요청 자체는 다시 재발급을 시도하지 않음)
   │
   └── [UNAUTHORIZED 또는 리프레시 토큰 없음] → [authStore.logout()] → [/login]
```

**로그아웃**

```text
[로그아웃 클릭]
   ↓
[POST /api/auth/logout   (서버 리프레시 토큰 폐기)]
   ↓
[authStore.logout()      (액세스·리프레시 토큰 및 memberStore 초기화)]
   ↓
[/login 으로 replace 이동 (뒤로가기로 복귀 불가)]
```

> 액세스 토큰은 stateless이므로 클라이언트 삭제가 실질적인 로그아웃이며,
> 서버 호출은 리프레시 토큰 재사용을 막기 위한 것이다. API 실패 시에도 클라이언트 상태는 반드시 초기화한다.

**회원 탈퇴**

```text
[회원 탈퇴 클릭]
   ↓
[WithdrawDialog 표시] ── [취소] → 대화상자 닫기
   ↓ [탈퇴]
[DELETE /api/members/me   (서버: status → WITHDRAWN, 리프레시 토큰 폐기)]
   ├── [204] → [authStore.logout()] → [/login 으로 replace 이동 ("회원 탈퇴가 완료되었습니다.")]
   └── [실패] → [대화상자 안에 오류 메시지 + 재시도]
```

> 탈퇴는 물리 삭제가 아닌 소프트 삭제이며, 검사 이력은 보존된다. 탈퇴한 계정으로 로그인하면 로그인 화면의 '탈퇴 회원-403' 상태("이용할 수 없는 계정입니다.")가 표시된다.

### 3.6.9 회원 정보 조회 및 탈퇴 정책

회원정보는 마이페이지에서 **조회 전용**으로 제공한다. 변경이 필요하면 관리자가 관리자 화면(ADM-04-1)에서 수정한다. 사용자는 마이페이지에서 **본인 탈퇴**만 할 수 있다.

**수정 정책**

| 항목 | 마이페이지에서 가능 여부 |
| ---- | -------- |
| 이름   | ❌        |
| 이메일  | ❌        |
| 성별   | ❌        |
| 출생년도 | ❌        |
| 회원 탈퇴 | ⭕ (`DELETE /api/members/me`) |

### 3.6.10 빈 상태

사용자가 아직 검사를 완료하지 않은 경우 다음과 같이 표시한다.

```text
┌─────────────────────────────────────────────────────────┐
│ 최근 검사 결과                                          │
├─────────────────────────────────────────────────────────┤
│ ┌─────────────────────────────────────────────────────┐ │
│ │                                                     │ │
│ │            아직 검사 이력이 없습니다.                  │ │
│ │                                                     │ │
│ │          ┌──────────────────────┐                   │ │
│ │          │   검사 시작하기 →     │                   │ │
│ │          └──────────────────────┘                   │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ (검사 결과 추이 섹션은 렌더링하지 않음)                     │
└─────────────────────────────────────────────────────────┘
```

**검사 시작하기** 클릭 시 `/surveys/p`로 이동한다.

| 결과 없음 | "검색 결과가 없습니다." | 결과 0건 |
| 조회 실패 | "검사 결과를 불러오지 못했습니다." | 조회 중 서비스·DB 예외 발생 |
| 삭제 확인 | 삭제 확인 문구 | 삭제 클릭 |
| 삭제 완료 | 플래시 메시지 "삭제되었습니다." + 목록에서 제거 | 처리 성공 |
| 삭제 실패 | 플래시 메시지 "처리 중 오류가 발생했습니다." | 처리 실패 |

### 4.6.4 처리 흐름

```text
검사 결과 목록 요청 → AdminResultController.list → AdminResultService.search
   → 활성(active=true) 결과 중 선택한 조건만 적용하여 조회
     (검사 종류·위험도·이름·기간, 동적 검색 + 페이징, 최신순)
   → 목록 + 총 N건 렌더링 (이름 검색어 일치 부분은 <mark>로 강조)

[삭제]
   → 확인
   → POST /admin/results/{id}/delete
   → SurveyResult.active = false
   → 목록에서 제외
```

> 화면의 "삭제"는 물리 삭제가 아니라 비활성화(soft delete)를 의미한다. 비활성 결과는 목록과 통계에서 제외한다.

# 7. 반응형 설계

사용자 화면(React)은 검사 대상이 휴대폰으로 바로 응시할 수 있도록 **모바일 우선**으로 설계한다. shadcn/ui가 사용하는 Tailwind CSS의 기본 브레이크포인트를 따른다. 관리자 화면(Thymeleaf)은 PC 업무용이므로 데스크톱 기준으로 설계하고, 좁은 화면에서는 레이아웃이 깨지지 않는 수준까지만 대응한다.

## 7.1 브레이크포인트

| 구분 | 화면 폭 | Tailwind 접두사 | 기준 기기 |
|---|---|---|---|
| 모바일 | 768px 미만 | (기본) | 스마트폰 |
| 태블릿 | 768px 이상 ~ 1024px 미만 | `md:` | 태블릿, 작은 노트북 |
| 데스크톱 | 1024px 이상 | `lg:` | PC |

## 7.2 사용자 화면 배치 규칙

| 화면 | 데스크톱 | 모바일 |
|---|---|---|
| 공통 헤더 | 로고 + 메뉴(검사하기·마이페이지·로그아웃) 가로 배치 | 로고 + 햄버거 버튼, 메뉴는 펼침 패널로 표시 |
| SCR-01 로그인 / SCR-02 회원가입 | 가운데 정렬 카드 (최대 폭 448px) | 카드가 화면 전체 폭 (좌우 여백 16px) |
| SCR-03·04 검사 | 문항 카드 가운데 정렬 (최대 폭 672px), 답변 선택지 3개 가로 배치 | 답변 선택지 3개를 세로로 쌓고 각 버튼을 화면 전체 폭으로 표시 |
| SCR-03·04 이전/다음 버튼 | 문항 카드 아래 좌우 배치 | 화면 하단에 고정해 스크롤 없이 누를 수 있게 함 |
| SCR-05 검사 결과 | 영역별 점수 카드 3개 가로 배치 | 영역별 점수 카드 세로 1열 |
| SCR-06 마이페이지 | 회원정보·추이 그래프·이력 표를 위에서 아래로 배치, 이력은 표 형태 | 추이 그래프는 가로 100% 폭, 이력은 표 대신 카드 목록(날짜·검사 종류·판정·점수·상세보기) |
| 확인창 (회원 탈퇴 등) | 화면 가운데 모달 | 화면 전체 폭 모달, 버튼 세로 배치 |

## 7.3 터치·크기 규칙

- 버튼·답변 선택지 등 누르는 요소는 높이 최소 48px, 요소 사이 간격 최소 8px로 잘못 누르는 일을 줄인다.
- 답변 선택지는 동그라미(라디오)만이 아니라 선택지 문구 영역 전체를 눌러도 선택되게 한다.
- 글자 크기는 화면 폭과 관계없이 6.2 타이포그래피 값을 유지한다 (모바일에서 글자를 줄이지 않음).
- 가로 스크롤이 생기지 않도록 모든 영역은 `max-width` + `width: 100%`로 배치한다.

## 7.4 관리자 화면

| 화면 폭 | 배치 |
|---|---|
| 1024px 이상 | 좌측 사이드바 + 본문 (2.2 레이아웃) |
| 1024px 미만 | 사이드바를 숨기고 헤더 메뉴로 이동, 대시보드 지표 카드는 2열 → 1열 |
| 표(회원·검사 결과 목록) | 폭이 부족하면 표 영역만 가로 스크롤 (`overflow-x: auto`) |

# 8. 접근성 설계

주 사용자가 인지 저하가 걱정되는 고령층과 그 보호자이므로, 읽기 쉽고 누르기 쉬운 화면을 기본으로 한다. 기준은 웹 콘텐츠 접근성 지침(WCAG 2.1) AA 수준이다.

| 구분 | 설계 기준 | 적용 화면 |
|---|---|---|
| 글자 크기 | 본문 16px 이상, 검사 문항 20px. 브라우저 확대(200%) 시에도 내용이 잘리지 않게 한다 | 전체 |
| 색 대비 | 글자와 배경의 명도 대비 4.5:1 이상 | 전체 |
| 색에만 의존 금지 | 판정은 색상과 함께 "정상/주의/위험" 글자를 항상 표시한다. 그래프의 점도 판정 글자를 툴팁으로 표시한다 | SCR-05, SCR-06, ADM-02·05·06 |
| 폼 레이블 | 모든 입력칸에 `<label>`을 연결하고, 필수 항목은 `*` 표시와 `aria-required="true"`를 함께 쓴다 | SCR-01, SCR-02, ADM-01, ADM-04-1 |
| 오류 안내 | 오류 문구를 입력칸 바로 아래에 표시하고 `aria-describedby`로 연결한다. 제출 실패 시 첫 번째 오류 입력칸으로 포커스를 옮긴다 | SCR-01, SCR-02, ADM-04-1 |
| 키보드 사용 | Tab으로 모든 버튼·입력칸에 이동할 수 있고, 포커스 테두리를 없애지 않는다. 답변 선택지는 방향키로 이동, Space로 선택한다 (shadcn `RadioGroup`) | 전체 |
| 진행 상태 | 진행 막대와 함께 "3 / 5" 글자를 표시한다 | SCR-03, SCR-04 |
| 알림 | 오류·완료 메시지(Alert, 플래시 메시지)는 `role="alert"`로 화면 낭독기가 읽게 한다 | 전체 |
| 그래프 대체 정보 | 점수 추이 그래프와 같은 내용을 검사 이력 표로 함께 제공한다 | SCR-06 |
| 페이지 정보 | `<html lang="ko">`, 화면마다 `<title>`을 다르게 지정한다 (예: "KDSQ-P 1차 검사 - 마음 기억") | 전체 |
| 시간 제한 | 검사 문항에 응답 시간 제한을 두지 않는다 | SCR-03, SCR-04 |
| 표 구조 | 관리자 목록 표는 `<th scope="col">`로 열 제목을 지정한다 | ADM-03·04·05 |
