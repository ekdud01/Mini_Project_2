| SCR-01 | 로그인   | `/login` | X | 이메일/비밀번호 입력, JWT 발급, 회원가입 이동 | `POST /api/auth/login` |

### 1.3 권한별 접근 정책

| 권한 | 접근 범위 | 비고 |
|---|---|---|
| 공개 | 로그인, 회원가입, 관리자 로그인 | 검사 및 마이페이지 접근 불가 |
| 사용자 | 공개 화면 + 검사 + 결과 + 마이페이지 | 회원정보는 조회 전용(수정은 관리자만), 본인 탈퇴 가능 |
| 관리자 | 관리자 로그인 후 관리자 전체 화면 | 회원정보·검사 결과 관리 가능 |
| 개발자(유지보수) | 화면 설계 범위 외 | 운영 데이터 조회 권한 없음 |

### 1.4 핵심 검사 흐름

```text
회원가입
   ↓
로그인
   ↓
KDSQ-P (1차) 5문항
   ↓
1차 합계 확인 (10점 만점, 화면 이동 판단용)
   ├── 0~3점 → POST /api/results → 서버 채점·정상 판정, 결과 1건 저장 → 결과 화면 → 종료
   │
   └── 4~10점 → 저장하지 않고 KDSQ-C (2차) 진행 (1차 답변은 화면에 보관)
                    ↓
             15문항 응답
                    ↓
      POST /api/results (1차 5문항 + 2차 15문항 답변)
                    ↓
      서버: 1차 재채점·검증, memoryScore + otherScore + adlScore 산출 (각 10점 만점)
            totalScore = memory + other + adl (30점 만점, 저장하지 않고 응답에 포함)
            firstScore + 영역별 점수를 결과 1건으로 저장
                    ↓
             ┌──────┴──────┐
             ↓             ↓
           0~5점          6~30점
            주의           위험
             └──────┬──────┘
                    ↓
             결과 화면
        (관리·추가 검진 안내 포함)
                    ↓
                 마이페이지
```

> 판정 기준은 문서 전체에서 **KDSQ-P 0\~3 정상 / 4\~10 2차 대상**, **KDSQ-C 0\~5 주의 / 6\~30 위험**으로 통일한다.
>
> **저장 정책**: 검사 1회당 결과는 1건만 저장한다. 2차 대상자가 KDSQ-C를 완료하지 않고 이탈하면 결과를 저장하지 않는다. 최종 채점·판정은 서버가 수행하며, 화면의 1차 합계는 2차 진행 여부 판단에만 사용한다.

# 2. 전체 레이아웃 구조

## 2.1 사용자 레이아웃

```text
┌─────────────────────────────────────────────────────────────┐
│  Header                                                     │
│  [KDSQ]         [검사하기]   [마이페이지]   [로그인/로그아웃]  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                     Main Content Area                       │
│                     (각 페이지 내용)                         │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│  Footer: ⓒ 2026 마음 기억                                   │
└─────────────────────────────────────────────────────────────┘
```

## 2.2 관리자 레이아웃

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ Header                                                                   │
│ [KDSQ 관리자]   [대시보드][회원 관리][검사 결과]   ○○○ 관리자님   [로그아웃]  │
├──────────────┬───────────────────────────────────────────────────────────┤
│ 사이드바      │  홈 > 회원 관리 > 회원 상세               ← Breadcrumb      │
│ 대시보드      │ ┌───────────────────────────────────────────────────────┐ │
│ 회원 관리     │ │       저장되었습니다.        ← 성공 시(초록, 자동 사라짐)   │ │
│ 검사 결과     │ │       처리 중 오류가 발생했습니다. ← 실패 시(빨강, 수동 닫기)│ │
│              │ └───────────────────────────────────────────────────────┘ │
│              │                    Main Content Area                     │
│              │                    (각 관리자 화면)                       │
├──────────────┴───────────────────────────────────────────────────────────┤
│ Footer: ⓒ 2026 마음 기억                                                 │
└──────────────────────────────────────────────────────────────────────────┘
```
> **헤더**: 로그인한 관리자 이름을 `sec:authentication="name"`으로 표시한다.
> **브레드크럼**: 대시보드를 제외한 모든 관리자 화면 상단에 표시하며, 마지막 단계는 클릭 불가(현재 위치)로 처리한다.
> **플래시 메시지**: 저장/수정/비활성화/삭제 등 처리 후 결과를 알려주는 공통 영역이며, 성공(초록)·실패(빨강) 두 종류만 사용한다.

# 3. 사용자 화면별 상세 설계

## 3.1 SCR-01 — 로그인 화면

```text
┌──────────────────────────────────────────────┐
│ Header                                       │
├──────────────────────────────────────────────┤
│                    KDSQ                      │
│              인지선별검사 플랫폼               │
│                                              │
│   이메일                                      │
│   ┌──────────────────────────────────────┐   │
│   │ example@email.com                    │   │

│                                              │

│   ┌──────────────────────────────────────┐   │
```

### 3.1.3 UI 컴포넌트 매핑

| 화면 요소      | 컴포넌트        | 라이브러리 컴포넌트        | 역할                               |
| :--------- | :---------- | :---------------- | :------------------------------- |
| 로그인 화면     | `LoginPage` | -                 | 화면 컨테이너, 로그인 성공 시 `/surveys/p`로 이동 |

| 로그인        | `Button`    | `Button` (shadcn) | 로그인 제출, 로딩 시 비활성화 및 스피너 표시       |
| 로그인 실패 메시지 | `Alert`     | `Alert` (shadcn)  | 로그인 실패 메시지 표시                    |

### 3.1.4 화면 상태

| 상태  | 표시 내용  | 트리거     |
| ------ | --------- | ----------- |
| **초기 상태** | 이메일/비밀번호 입력 폼 및 로그인 버튼 표시   | 로그인 화면 진입           |
| **입력 중**  | 사용자가 입력한 이메일/비밀번호 표시          | 각 입력 필드에 값 입력       |
| **입력칸 공백**  | "이메일과 비밀번호를 입력해주세요." 메시지 표시   | 필수값 누락 (제출 차단)       |
| **입력 오류** | "올바른 이메일 형식이 아닙니다." 메시지 표시   | 이메일 형식 오류 (제출 차단)    |
| **로그인 진행 중** | 버튼 비활성화 + CircularProgress       | 로그인 버튼 클릭           |
| **로그인 성공**  | 로그인 처리 후 검사 화면(/surveys/p)으로 이동         | 로그인 API 성공          |
| **로그인 인증 실패-401**  | "이메일 또는 비밀번호를 확인해주세요." 메시지 표시   | 이메일 또는 비밀번호 불일치     |
| **탈퇴 회원-403**  | "이용할 수 없는 계정입니다." 메시지 표시   | 이메일 또는 비밀번호 불일치     |
| **네트워크 오류-5xx** | "일시적인 오류입니다. 잠시 후 다시 시도해주세요." 메시지 표시 | 서버 연결 실패            |
| **회원가입 이동** | 회원가입 화면(/register)으로 이동                | "회원가입하기" 클릭         |

> 보안상 존재하지 않는 이메일과 비밀번호 불일치를 구분해 노출하지 않는다.

### 3.1.5 사용자 인터랙션 흐름

```text
[authStore.isAuthenticated 확인]
   → [false] → [/login]
               ↓
         [이메일/비밀번호 입력]
           → [입력값 상태 업데이트]
           → [로그인 버튼 클릭] → loading = true
                 → [POST /api/auth/login]
                    → [200] → [토큰 저장(authStore)-로그인 처리 + /surveys/p 이동]
                    → [401] → [error: "이메일 또는 비밀번호를 확인해주세요."]
                    → [5xx] → [error: "일시적인 오류입니다. 잠시 후 다시 시도해주세요."]
   → [true] → [/surveys/p]

[회원가입하기 클릭]
    → [회원가입 화면으로 이동]
```

### 3.4.4 문항 영역 및 점수 구성

KDSQ-C는 총 15문항으로 구성되며, 문항 번호에 따라 3개 영역으로 구분하여 점수를 집계한다.

| 영역                    | 문항    | 점수 필드         | 설명                   |
| --------------------- | ----- | ------------- | -------------------- |
| **기억력 (KDSQ-M)**      | 1~5   | `memoryScore` | 기억력 관련 문항 점수 합계      |
| **기타 인지기능 (KDSQ-O)**  | 6~10  | `otherScore`  | 기타 인지기능 관련 문항 점수 합계  |
| **일상생활수행능력 (KDSQ-A)** | 11~15 | `adlScore`    | 일상생활수행능력 관련 문항 점수 합계 |
| **전체**                | 1~15  | `totalScore`  | 3개 영역 점수의 합계 (저장하지 않고 서버가 계산해 응답) |

```text
memoryScore = Q1 + Q2 + Q3 + Q4 + Q5
otherScore  = Q6 + Q7 + Q8 + Q9 + Q10
adlScore    = Q11 + Q12 + Q13 + Q14 + Q15

totalScore = memoryScore + otherScore + adlScore
```

> 문항별 `answers`는 저장하지 않는다. 위 계산은 서버(ScoringService)가 수행하며, `firstScore`, `memoryScore`, `otherScore`, `adlScore`를 결과 1건에 저장한다. `totalScore`는 서버가 계산하여 응답에 포함한다.

| **2차 진행 불가**   | "1차 검사부터 다시 진행해주세요." 안내 후 `/surveys/p` 이동 | 422 `KDSQ_C_NOT_ALLOWED` |
| **제출 실패**       | 검사 제출 실패 메시지 표시                           | `POST /api/results` 실패  |
| **네트워크 오류**     | "네트워크 오류가 발생했습니다. 잠시 후 다시 시도해주세요." 메시지 표시 | 서버 연결 실패 

### 3.4.6 상태 및 데이터 정의

| 상태 변수             | 타입                    | 설명                                    |
| ----------------- | --------------------- | ------------------------------------- |
| `questions`       | `Question[]`          | KDSQ-C 15개 검사 문항 목록                   |
| `currentQuestion` | `number`              | 현재 문항 번호                              |
| `answers`         | `Answer[]` / `Record` | 검사 진행 중 화면에서 사용하는 답변 상태               |
| `loading`         | `boolean`             | 검사 문항 조회 중 여부                         |
| `submitting`      | `boolean`             | 검사 결과 제출 중 여부                         |
| `surveyId`        | `number`              | KDSQ-C 설문 ID (`GET /api/surveys`로 확인) |
| `firstAnswers`    | `Answer[]`            | 1차 답변 5개 (resultStore의 `pendingFirstAnswers`) |

> **데이터 저장 정책**: 문항별 개별 응답(answers)은 저장하지 않고, 서버가 채점한 `firstScore` / `memoryScore` / `otherScore` / `adlScore`를 `SurveyResult` 1건에 저장한다. `totalScore`는 저장하지 않고 서버가 계산해 응답한다. 이 점수를 기반으로 영역별 통계(Admin 대시보드)를 제공한다. 2차 제출 성공 시 `pendingFirstAnswers`를 비운다.

### 3.4.7 사용자 인터랙션 흐름

```text
[KDSQ-P 4점 이상]
   → KDSQ-C 안내
   → GET /api/surveys/{surveyId}/questions
   → 15문항 진행
   → 마지막 문항 제출
   → POST /api/results {surveyId, firstAnswers, answers}
   → 서버: 1차 재채점·검증, 영역별 점수·totalScore 산출, 결과 1건 저장
   → 응답 riskLevel 수신
      ┌──────────────┴──────────────┐
      ↓                             ↓
    0~5점                         6~30점
      ↓                             ↓
     주의                          위험
      └──────────────┬──────────────┘
                     ↓
              결과 화면 이동
```

| **날짜** | 검사 완료일           |
| **검사** | KDSQ-P 또는 KDSQ-C |
| **총점** | KDSQ-P로 끝난 결과는 `firstScore`(10점 만점), KDSQ-C까지 수행한 결과는 `totalScore`(30점 만점) |
| **결과** | 검사 점수에 따른 결과 유형  |

**결과 유형**

| 검사     |   점수 | 표시 결과       |
| ------ | ---: | ----------- |
| KDSQ-P |  0~3 | 정상          |
| KDSQ-C |  0~5 | 주의          |
| KDSQ-C | 6~30 | 위험      |

> KDSQ-P 4~10점(2차 대상)은 2차까지 완료해야 저장되므로 이력에 나타나지 않는다.

### 3.6.7 표시 규칙

| 원본 값 | 화면 표기 |
| :--- | :--- |
| `gender: MALE / FEMALE` | 남성 / 여성 |
| `birthYear: 1960` | 1960 (만 66세) — 현재연도 − 출생년도 |
| `examType: KDSQ_P / KDSQ_C` | KDSQ-P / KDSQ-C |
| `riskLevel: Normal` | `정상` Chip |
| `riskLevel: Borderline` | `주의` Chip |
| `riskLevel: HighRisk` | `위험` Chip |
| `createdAt` | `YYYY-MM-DD` (시각 생략) |
| 영역별 점수·총점 `null` | `-` |

### 3.6.8 사용자 인터랙션 흐름

```text
[마이페이지 클릭]
   ↓
[ProtectedRoute 통과 확인 (토큰 유무)]
   ↓
[MyPage 마운트] → loading = true
   ↓
[GET /api/members/me]        ─┐
[GET /api/members/me/results]     ─┴─ 병렬 호출 (Promise.all)
   → [두 요청 모두 성공]
          → [응답의 totalScore / firstScore를 그대로 표시 (프론트 계산 없음)]
                 ↓
         [resultHistory.length === 0 ?]
              → [Yes] → [ProfileCard + 빈 상태 안내 (그래프 미렌더)]
              → [No]  → [ProfileCard + ExamHistoryTable + ExamTrendChart]

   → [401] → [토큰 만료] → [아래 토큰 만료·재발급 플로우]

   → [그 외 오류] → [Alert + 다시 시도 버튼]
```

**토큰 만료 / 재발급**

```text
[API 응답 401 수신 (axios 응답 인터셉터)]
   ↓
[리프레시 토큰 보유?]
   │
   ├── [Yes] → [POST /api/auth/reissue]
   │            ├── [성공] → [새 액세스 토큰 저장] → [실패했던 요청 1회 재시도]
   │            └── [실패] → [authStore.logout()] → [/login ("다시 로그인해주세요.")]
   │
   └── [No]  → [authStore.logout()] → [/login]
```

**로그아웃**

```text
[로그아웃 클릭]
   ↓
[POST /api/auth/logout   (서버 리프레시 토큰 폐기)]
   ↓
[authStore.logout()      (액세스·리프레시 토큰 및 memberStore 초기화)]
   ↓
[/login 으로 replace 이동 (뒤로가기로 복귀 불가)]
```

> 액세스 토큰은 stateless이므로 클라이언트 삭제가 실질적인 로그아웃이며,
> 서버 호출은 리프레시 토큰 재사용을 막기 위한 것이다. API 실패 시에도 클라이언트 상태는 반드시 초기화한다.

**회원 탈퇴**

```text
[회원 탈퇴 클릭]
   ↓
[WithdrawDialog 표시] ── [취소] → 대화상자 닫기
   ↓ [탈퇴]
[DELETE /api/members/me   (서버: status → WITHDRAWN, 리프레시 토큰 폐기)]
   ├── [204] → [authStore.logout()] → [/login 으로 replace 이동 ("회원 탈퇴가 완료되었습니다.")]
   └── [실패] → [대화상자 안에 오류 메시지 + 재시도]
```

> 탈퇴는 물리 삭제가 아닌 소프트 삭제이며, 검사 이력은 보존된다. 탈퇴한 계정으로 로그인하면 로그인 화면의 '탈퇴 회원-403' 상태("이용할 수 없는 계정입니다.")가 표시된다.

### 3.6.9 회원 정보 조회 및 탈퇴 정책

회원정보는 마이페이지에서 **조회 전용**으로 제공한다. 변경이 필요하면 관리자가 관리자 화면(ADM-04-1)에서 수정한다. 사용자는 마이페이지에서 **본인 탈퇴**만 할 수 있다.

**수정 정책**

| 항목 | 마이페이지에서 가능 여부 |
| ---- | -------- |
| 이름   | ❌        |
| 이메일  | ❌        |
| 성별   | ❌        |
| 출생년도 | ❌        |
| 회원 탈퇴 | ⭕ (`DELETE /api/members/me`) |

### 3.6.10 빈 상태

사용자가 아직 검사를 완료하지 않은 경우 다음과 같이 표시한다.

### 4.4.4 처리 흐름

```text

   → 회원정보 + 검사이력 조회

   → /admin/members/{id}/edit
```

> 계정 비활성화는 물리 삭제가 아닌 상태값 변경으로 처리하며, 연결된 검사 결과는 보존한다.
