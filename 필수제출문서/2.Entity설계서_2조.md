## 1. Entity 설계 개요

### 1.1 설계 목적
> JPA Entity 클래스 설계를 통해 객체-관계 매핑(ORM)을 정의하고,
> KDSQ 인지선별검사 비즈니스 도메인을 코드로 표현하여 데이터 무결성과 유지보수성이 용이한 시스템을 구축

### 1.2 설계 원칙
- **단일 책임 원칙**: 하나의 Entity는 하나의 비즈니스 개념만 표현
- **도메인별 패키지 분리**: 설문 도메인(`survey` 패키지: Survey, Question)과 결과 도메인(`result` 패키지: SurveyResult, Solution, ScoringService)을 분리. 결과 도메인만 설문 도메인을 참조한다.
- **소프트 삭제(Soft Delete) 적용**: 회원 탈퇴 시 UserStatus를 WITHDRAWN으로 변경하고, 관리자의 검사 결과 삭제는 `active = false`로 처리하여 검사 통계 및 이력 데이터의 정합성 유지
- **캡슐화 및 불변성**: 비즈니스 로직을 Entity 내부에 구현하고 무분별한 Setter 지양
- **연관관계 최소화**: 필요한 관계만 매핑하여 복잡도 감소
- **정규화 우선**: 검사 유형은 SurveyResult에 중복 저장하지 않고 연관된 Survey에서 조회

### 1.3 기술 스택
- **ORM 프레임워크**: Spring Data JPA [Version]
- **데이터베이스**: MariaDB [Version]
- **검증 프레임워크**: Bean Validation [Version]
- **감사 기능**: Spring Data JPA Auditing

#### 4.1.2 필드 상세 명세
| 필드명 | 데이터 타입 | 컬럼명 | 제약조건 | 설명 | 비즈니스 규칙 |
|--------|-------------|--------|----------|------|---------------|
| **id** | `Long` | `id` | PK, NOT NULL, AUTO_INCREMENT | 회원 고유 식별자 | BaseEntity 상속, 시스템 자동 생성 |
| **email** | `String` | `email` | UNIQUE, NOT NULL, LENGTH(100) | 이메일 | 로그인 ID 겸용 |
| **password** | `String` | `password` | NOT NULL, LENGTH(255) | 비밀번호 | BCrypt 암호화 |
| **name** | `String` | `name` | NOT NULL, LENGTH(50) | 환자명 | 필수 입력 |
| **gender** | `Gender` | `gender` | ENUM, NULL 허용 | 성별 | MALE, FEMALE. MEMBER는 회원가입 DTO에서 필수(@NotNull), ADMIN 계정은 환자 정보가 없으므로 null |
| **birthYear** | `Integer` | `birth_year` | NULL 허용 | 출생년도 | 통계 산출용. MEMBER는 회원가입 DTO에서 필수(@NotNull, 1900~현재연도), ADMIN 계정은 null |
| **status** | `UserStatus` | `status` | NOT NULL, ENUM | 회원 상태 | ACTIVE, WITHDRAWN (소프트 삭제). 본인 탈퇴와 관리자 탈퇴 처리 모두 WITHDRAWN |
| **role** | `Role` | `role` | NOT NULL, ENUM, DEFAULT('MEMBER') | 권한 | 회원가입 시 MEMBER, 관리자 계정은 초기 데이터로 ADMIN 등록 |
| **createdAt** | `LocalDateTime` | `created_at` | NOT NULL, 수정 불가 | 가입일 | BaseEntity 상속, JPA Auditing이 가입 시 자동 기록 (입력받지 않음) |

#### 4.2.2 구현 코드 예시
```java
/**
 * 설문지 Entity (survey 패키지)
 */
@Entity
@Table(name = "surveys")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class Survey extends BaseEntity {

    @Enumerated(EnumType.STRING)
    @Column(name = "exam_type", nullable = false, unique = true)
    private ExamType examType;

    @Column(nullable = false, length = 100)
    private String title;

    @Column(columnDefinition = "TEXT")
    private String description;

    @OneToMany(mappedBy = "survey", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    @OrderBy("questionNumber ASC")
    private List<Question> questions = new ArrayList<>();

    /** 설문 생성 (초기 데이터·테스트용). 실제 설문은 data.sql로 등록 */
    public static Survey create(ExamType examType, String title, String description) {
        Survey survey = new Survey();
        survey.examType = examType;
        survey.title = title;
        survey.description = description;
        return survey;
    }
}

/**
 * 문항 Entity (survey 패키지)
 */
@Entity
@Table(name = "questions")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class Question extends BaseEntity {

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "survey_id", nullable = false)
    private Survey survey;

    @Column(name = "question_number", nullable = false)
    private Integer questionNumber;

    @Column(nullable = false, columnDefinition = "TEXT")
    private String content;
}
```

### 4.3 SurveyResult Entity

검사 1회당 결과 1건을 저장한다. KDSQ-P 0\~3점이면 1차 완료 시, KDSQ-P 4점 이상이면 KDSQ-C 완료 시 1·2차 점수를 합쳐 저장한다. 2차 대상자가 중간 이탈하면 저장하지 않는다.

#### 4.3.1 필드 상세 명세
| 필드명 | 데이터 타입 | 컬럼명 | 제약조건 | 설명 | 비즈니스 규칙 |
|--------|-------------|--------|----------|------|---------------|
| **id** | `Long` | `id` | PK, NOT NULL, AUTO_INCREMENT | 검사결과 고유 식별자 | BaseEntity 상속, 시스템 자동 생성 |
| **member** | `Member` | `member_id` | FK, NOT NULL | 검사 회원 | members 참조 |
| **survey** | `Survey` | `survey_id` | FK, NOT NULL | 마지막으로 완료한 설문 | 1차에서 종료 시 KDSQ-P, 2차까지 수행 시 KDSQ-C. 검사 유형은 `survey.examType`으로 조회 |
| **firstScore** | `Integer` | `first_score` | NOT NULL | 1차(KDSQ-P) 점수 | 0\~10점, 모든 결과에 존재 |
| **memoryScore** | `Integer` | `memory_score` | NULL 허용 | 기억력 영역 점수 | KDSQ-C (1~5번 합산), KDSQ-P로 끝난 결과는 null |
| **otherScore** | `Integer` | `other_score` | NULL 허용 | 기타 인지기능 영역 점수 | KDSQ-C (6~10번 합산), KDSQ-P로 끝난 결과는 null |
| **adlScore** | `Integer` | `adl_score` | NULL 허용 | 일상생활 수행능력 점수 | KDSQ-C (11~15번 합산), KDSQ-P로 끝난 결과는 null |
| **riskLevel** | `RiskLevel` | `risk_level` | NOT NULL, ENUM | 판정 등급 | Normal, Borderline, HighRisk |
| **active** | `Boolean` | `active` | NOT NULL, DEFAULT(true) | 활성 여부 | 관리자 삭제 시 false (소프트 삭제), 목록·통계에서 제외 |

> 영역별 점수를 nullable로 두는 이유: '검사를 하지 않음(null)'과 '0점'을 구분하고, 관리자 대시보드의 영역별 평균(`AVG`)이 null을 자동 제외하여 KDSQ-C 수행자만으로 계산되도록 하기 위함.

#### 4.3.2 구현 코드 예시
```java
/**
 * 검사결과 Entity (result 패키지)
 */
@Entity
@Table(name = "survey_results")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class SurveyResult extends BaseEntity {

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "member_id", nullable = false)
    private Member member;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "survey_id", nullable = false)
    private Survey survey; // 마지막으로 완료한 설문 (KDSQ-P 또는 KDSQ-C)

    @Column(name = "first_score", nullable = false)
    private Integer firstScore;

    @Column(name = "memory_score")
    private Integer memoryScore; // KDSQ-P로 끝난 결과는 null

    @Column(name = "other_score")
    private Integer otherScore;

    @Column(name = "adl_score")
    private Integer adlScore;

    @Enumerated(EnumType.STRING)
    @Column(name = "risk_level", nullable = false)
    private RiskLevel riskLevel;

    @Column(nullable = false)
    private Boolean active = true;

    // 비즈니스 메서드
    public ExamType getExamType() {
        return this.survey.getExamType();
    }

    /** KDSQ-C 총점. KDSQ-P로 끝난 결과는 null (저장하지 않고 계산) */
    public Integer getTotalScore() {
        if (getExamType() == ExamType.KDSQ_P) {
            return null;
        }
        return this.memoryScore + this.otherScore + this.adlScore;
    }

    /** 1차(KDSQ-P) 0~3점으로 검사가 끝난 경우 */
    public static SurveyResult createFirstOnly(Member member, Survey pSurvey, int firstScore) {
        if (firstScore >= 4) {
            throw new BusinessException(ErrorCode.KDSQ_C_REQUIRED);
        }
        SurveyResult result = new SurveyResult();
        result.member = member;
        result.survey = pSurvey;
        result.firstScore = firstScore;
        result.riskLevel = RiskLevel.Normal;
        return result;
    }

    /** 1차 4점 이상 후 2차(KDSQ-C)까지 완료한 경우 */
    public static SurveyResult createWithSecond(Member member, Survey cSurvey, int firstScore,
                                                int memoryScore, int otherScore, int adlScore) {
        if (firstScore < 4) {
            throw new BusinessException(ErrorCode.KDSQ_C_NOT_ALLOWED);
        }
        SurveyResult result = new SurveyResult();
        result.member = member;
        result.survey = cSurvey;
        result.firstScore = firstScore;
        result.memoryScore = memoryScore;
        result.otherScore = otherScore;
        result.adlScore = adlScore;
        result.riskLevel = result.evaluateRisk();
        return result;
    }

    private RiskLevel evaluateRisk() {
        if (getExamType() == ExamType.KDSQ_P) {
            return RiskLevel.Normal; // 1차에서 끝난 결과는 0~3점만 저장되므로 항상 정상
        }
        return (getTotalScore() <= 5) ? RiskLevel.Borderline : RiskLevel.HighRisk;
    }

    /** 관리자 삭제 (소프트 삭제) */
    public void deactivate() {
        this.active = false;
    }
}
```

#### 4.3.3 채점 서비스 (ScoringService)
```java
/**
 * 제출된 답변을 채점하여 SurveyResult를 생성 (result 패키지)
 * - 프론트엔드의 1차 합계는 화면 이동용이며, 최종 채점·판정은 이 서비스가 담당한다.
 */
@Service
@RequiredArgsConstructor
public class ScoringService {

    private final QuestionRepository questionRepository;

    /** KDSQ-P 5문항 합계 */
    public int scoreFirst(Survey pSurvey, List<AnswerDto> firstAnswers) {
        Map<Integer, Integer> byNumber = toScoreByQuestionNumber(pSurvey, firstAnswers, 5);
        return sum(byNumber, 1, 5);
    }

    /** KDSQ-C 15문항 영역별 합계: [기억력(1~5), 기타 인지(6~10), 일상생활(11~15)] */
    public int[] scoreSecond(Survey cSurvey, List<AnswerDto> answers) {
        Map<Integer, Integer> byNumber = toScoreByQuestionNumber(cSurvey, answers, 15);
        return new int[] { sum(byNumber, 1, 5), sum(byNumber, 6, 10), sum(byNumber, 11, 15) };
    }

    /**
     * 답변의 questionId를 해당 설문의 문항 번호로 바꾼다.
     * - 개수가 다르면 INVALID_ANSWER_COUNT, 다른 설문의 문항이면 QUESTION_NOT_FOUND
     */
    private Map<Integer, Integer> toScoreByQuestionNumber(Survey survey, List<AnswerDto> answers, int expected) {
        if (answers == null || answers.size() != expected) {
            throw new BusinessException(ErrorCode.INVALID_ANSWER_COUNT);
        }
        Map<Long, Integer> numberById = questionRepository
                .findBySurveyIdOrderByQuestionNumberAsc(survey.getId()).stream()
                .collect(Collectors.toMap(Question::getId, Question::getQuestionNumber));
        Map<Integer, Integer> result = new HashMap<>();
        for (AnswerDto a : answers) {
            Integer number = numberById.get(a.getQuestionId());
            if (number == null) throw new BusinessException(ErrorCode.QUESTION_NOT_FOUND);
            result.put(number, a.getScore());   // score 0~2는 DTO의 @Min(0) @Max(2)로 검증됨
        }
        return result;
    }

    private int sum(Map<Integer, Integer> byNumber, int from, int to) {
        return IntStream.rangeClosed(from, to).map(n -> byNumber.getOrDefault(n, 0)).sum();
    }
}
```

## 6. 연관관계 매핑 전략

### 6.1 연관관계 매핑 규칙
| 관계 유형 | 기본 전략 | 이유 | 예외 상황 |
|----------|-----------|------|-----------|
| **@ManyToOne** | LAZY | 성능 최적화 | 필수 조회 데이터는 EAGER |
| **@OneToMany** | LAZY | N+1 문제 방지 | 소량 데이터는 EAGER |
| **@OneToOne** | LAZY | 일관성 유지 | 항상 함께 조회하는 경우 EAGER |
| **@ManyToMany** | 사용 금지 | 복잡성 증가 | 중간 테이블로 대체 |

### 6.2 연관관계 요약
| 관계 | 매핑 | 설명 |
|------|------|------|
| Member 1:N SurveyResult | `SurveyResult.member` (@ManyToOne) / `Member.surveyResults` (@OneToMany) | 회원별 검사 이력 |
| Survey 1:N Question | `Question.survey` (@ManyToOne) / `Survey.questions` (@OneToMany) | 설문별 문항 |
| Survey 1:N SurveyResult | `SurveyResult.survey` (@ManyToOne, 단방향) | 결과가 마지막으로 완료한 설문을 참조. 설문 도메인은 결과를 알지 못하므로 Survey 쪽 컬렉션은 두지 않음 |

### 8.0 쿼리 작성 방식 선택 기준

쿼리의 복잡도에 따라 작성 방식을 나누어 사용한다.

| 상황 | 방식 | 적용 예 |
|------|------|---------|
| 단순 조회 (조건 1~2개) | 쿼리 메서드 (메서드 이름으로 쿼리 생성) | `findByEmail`, `existsByEmail`, `countByActiveTrue`, `countByRoleAndStatus` |

| DB 전용 기능이 꼭 필요한 경우 | Native SQL | 사용하지 않음 (DB 독립성 유지) |

### 8.1 N+1 문제 해결

연관 엔티티(`member`, `survey`)를 목록·상세에서 함께 보여줄 때는 LAZY 로딩으로 행마다 추가 쿼리가 발생하지 않도록 **fetch join** 또는 **`@EntityGraph`**로 한 번에 조회한다.

| 조회 | 함께 가져오는 연관 | 방법 |
|---|---|---|
| 결과 상세 (`findActiveDetailById`) | member, survey | `JOIN FETCH` |
| 마이페이지 이력 (`findByMemberIdOrderByCreatedAtDesc`) | survey | `JOIN FETCH` + 별도 countQuery (페이징) |
| 회원 상세 이력 (`findActiveByMemberId`) | survey | `@EntityGraph` |
| 검사 결과 목록 (`findAll(Specification, Pageable)`) | member, survey | `@EntityGraph` (Specification에서 fetch join을 쓰면 count 쿼리가 깨지므로 EntityGraph 사용) |
| 대시보드 최근 위험 목록 (`findRecentByRiskLevel`) | member, survey | `@EntityGraph` |

> 컬렉션(`@OneToMany`)은 페이징 쿼리에서 fetch join하지 않는다. 위 조회는 모두 `@ManyToOne` 연관만 함께 가져오므로 페이징과 함께 사용해도 안전하다.

### 8.3 관리자 대시보드 쿼리 (ADM-02)

대시보드는 `AdminDashboardController → AdminStatisticsService → Repository` 순서로 구성한다. **Repository는 DB에서 개수·평균·월별 묶음을 집계만** 하고, **비율(%) 계산·반올림·빈 달 채우기·DTO 조립은 서비스**(8.5)에서 한다.

| 대시보드 항목 | 쿼리 (Repository) | 서비스에서 추가로 하는 일 |
|---|---|---|
| 전체 회원 수(활성) | `MemberRepository.countByRoleAndStatus(MEMBER, ACTIVE)` | — |
| 전체 검사 건수(활성) | `SurveyResultRepository.countByActiveTrue()` | — |
| 위험도 분포 | `countGroupByRiskLevel()` → 등급별 건수 | 건수 → 비율(%) 계산, 결과가 없는 등급은 0 |
| 종합점수 평균 / 영역별 평균 | `findScoreAverages()` → 종합·기억력·기타 인지·일상생활 평균 | 소수점 첫째 자리 반올림, 결과 없으면 0 |
| 월별 평균 점수 / 월별 검사 건수 추이 | `findMonthlyTrend(from)` → 최근 12개월 월별 건수·총점 평균 | 데이터가 없는 달을 건수 0으로 채워 12개월 연속으로 구성 |
| 최근 위험 검사 목록 | `findRecentByRiskLevel(HighRisk, PageRequest.of(0, 5))` | DTO 변환 |

> 집계 기준: 모든 대시보드 쿼리는 관리자가 삭제하지 않은 결과(`active = true`)만 대상으로 한다. **검사 건수는 1차에서 끝난 결과를 포함한 전체**, **점수 평균은 KDSQ-C 수행 결과만** 대상이다(`AVG`가 null인 KDSQ-P 종료 결과를 자동 제외).

```java
public interface SurveyResultRepository extends JpaRepository<SurveyResult, Long>,
                                                JpaSpecificationExecutor<SurveyResult> {

    // 전체 검사 건수(활성)
    long countByActiveTrue();

    // 위험도 분포: 등급별 건수 (인터페이스 프로젝션)
    @Query("SELECT r.riskLevel AS riskLevel, COUNT(r) AS count " +
           "FROM SurveyResult r WHERE r.active = true GROUP BY r.riskLevel")
    List<RiskLevelCount> countGroupByRiskLevel();

    // 종합점수 평균 + 영역별 평균 (KDSQ-C 수행 결과만, 1행)
    @Query("SELECT AVG(r.memoryScore + r.otherScore + r.adlScore) AS avgTotal, " +
           "AVG(r.memoryScore) AS avgMemory, AVG(r.otherScore) AS avgOther, AVG(r.adlScore) AS avgAdl " +
           "FROM SurveyResult r WHERE r.active = true")
    ScoreAverages findScoreAverages();

    // 월별 추이: from(최근 12개월 시작일) 이후, 월별 검사 건수와 KDSQ-C 총점 평균
    @Query("SELECT YEAR(r.createdAt) AS year, MONTH(r.createdAt) AS month, " +
           "COUNT(r) AS resultCount, AVG(r.memoryScore + r.otherScore + r.adlScore) AS avgTotal " +
           "FROM SurveyResult r WHERE r.active = true AND r.createdAt >= :from " +
           "GROUP BY YEAR(r.createdAt), MONTH(r.createdAt) " +
           "ORDER BY YEAR(r.createdAt), MONTH(r.createdAt)")
    List<MonthlyTrend> findMonthlyTrend(@Param("from") LocalDateTime from);

    // 최근 위험 검사 목록: 건수는 호출하는 쪽에서 Pageable로 지정 (대시보드는 5건)
    @EntityGraph(attributePaths = {"member", "survey"})
    @Query("SELECT r FROM SurveyResult r " +
           "WHERE r.riskLevel = :riskLevel AND r.active = true " +
           "ORDER BY r.createdAt DESC")
    List<SurveyResult> findRecentByRiskLevel(@Param("riskLevel") RiskLevel riskLevel, Pageable pageable);
```

#### 8.4.1 검사 결과 복합 검색 (ADM-05) — Specification 동적 쿼리
검사 종류·위험도·회원 이름·기간은 **선택한 조건만** WHERE에 붙어야 하므로, 고정 JPQL 대신 Spring Data JPA `Specification`으로 조건을 조합한다. (목록 파라미터에 `IS NULL`을 쓰는 JPQL은 위험도를 선택하지 않았을 때 오동작할 수 있어 사용하지 않는다.)

```java
public class SurveyResultSpecs {

    public static Specification<SurveyResult> isActive() {
        return (root, query, cb) -> cb.isTrue(root.get("active"));
    }

    public static Specification<SurveyResult> examTypeEq(ExamType examType) {
        return (root, query, cb) -> examType == null ? null
                : cb.equal(root.join("survey").get("examType"), examType);
    }

    public static Specification<SurveyResult> riskLevelIn(List<RiskLevel> riskLevels) {
        return (root, query, cb) -> (riskLevels == null || riskLevels.isEmpty()) ? null
                : root.get("riskLevel").in(riskLevels);
    }

    public static Specification<SurveyResult> memberNameContains(String name) {
        return (root, query, cb) -> !StringUtils.hasText(name) ? null
                : cb.like(root.join("member").get("name"), "%" + name.trim() + "%");
    }

    public static Specification<SurveyResult> createdBetween(LocalDate from, LocalDate to) {
        return (root, query, cb) -> {
            List<Predicate> predicates = new ArrayList<>();
            if (from != null) predicates.add(cb.greaterThanOrEqualTo(root.get("createdAt"), from.atStartOfDay()));
            if (to != null)   predicates.add(cb.lessThan(root.get("createdAt"), to.plusDays(1).atStartOfDay()));
            return predicates.isEmpty() ? null : cb.and(predicates.toArray(new Predicate[0]));
        };
    }
}

// SurveyResultRepository: 목록 조회 시 member·survey를 함께 가져와 N+1 방지
@EntityGraph(attributePaths = {"member", "survey"})
Page<SurveyResult> findAll(Specification<SurveyResult> spec, Pageable pageable);

// AdminResultService.search() — 조건이 null(또는 빈 값)이면 해당 Specification은 무시된다
Specification<SurveyResult> spec = Specification.where(SurveyResultSpecs.isActive())
        .and(SurveyResultSpecs.examTypeEq(cond.getExamType()))
        .and(SurveyResultSpecs.riskLevelIn(cond.getRiskLevels()))
        .and(SurveyResultSpecs.memberNameContains(cond.getName()))
        .and(SurveyResultSpecs.createdBetween(cond.getFrom(), cond.getTo()));
Page<SurveyResult> page = surveyResultRepository.findAll(spec,
        PageRequest.of(cond.getPage(), 20, Sort.by(Sort.Direction.DESC, "createdAt")));
```

### 8.5 대시보드 데이터 조립 (AdminStatisticsService)

쿼리 결과를 화면용 값으로 가공하여 `DashboardStatsDto` 하나로 묶고, 컨트롤러가 `model.addAttribute("stats", dto)`로 Thymeleaf에 전달한다.

```java
@Service
@RequiredArgsConstructor
@Transactional(readOnly = true)
public class AdminStatisticsService {

    private final MemberRepository memberRepository;
    private final SurveyResultRepository surveyResultRepository;

    public DashboardStatsDto getDashboard() {
        long totalMembers = memberRepository.countByRoleAndStatus(Role.MEMBER, UserStatus.ACTIVE);
        long totalResults = surveyResultRepository.countByActiveTrue();

        // 위험도 분포: 건수 → 비율(%), 결과가 없는 등급은 0
        Map<RiskLevel, Long> counts = new EnumMap<>(RiskLevel.class);
        for (RiskLevel level : RiskLevel.values()) counts.put(level, 0L);
        surveyResultRepository.countGroupByRiskLevel()
                .forEach(c -> counts.put(c.getRiskLevel(), c.getCount()));
        Map<RiskLevel, Double> ratios = new EnumMap<>(RiskLevel.class);
        counts.forEach((level, cnt) -> ratios.put(level, totalResults == 0 ? 0.0 : round1(cnt * 100.0 / totalResults)));

        // 종합·영역별 평균: 소수점 첫째 자리 반올림, 결과 없으면 0
        ScoreAverages avg = surveyResultRepository.findScoreAverages();

        // 월별 추이: 최근 12개월, 데이터가 없는 달은 0으로 채움
        YearMonth start = YearMonth.now().minusMonths(11);
        Map<YearMonth, MonthlyTrend> byMonth = surveyResultRepository
                .findMonthlyTrend(start.atDay(1).atStartOfDay()).stream()
                .collect(Collectors.toMap(t -> YearMonth.of(t.getYear(), t.getMonth()), t -> t));
        List<MonthlyPointDto> monthly = IntStream.range(0, 12)
                .mapToObj(start::plusMonths)
                .map(ym -> {
                    MonthlyTrend t = byMonth.get(ym);
                    return new MonthlyPointDto(ym.toString(),
                            t == null ? 0 : t.getResultCount(),
                            t == null ? 0.0 : round1(nvl(t.getAvgTotal())));
                })
                .toList();

        List<SurveyResult> recentHighRisk =
                surveyResultRepository.findRecentByRiskLevel(RiskLevel.HighRisk, PageRequest.of(0, 5));

        return DashboardStatsDto.of(totalMembers, totalResults, ratios,
                round1(nvl(avg.getAvgTotal())), round1(nvl(avg.getAvgMemory())),
                round1(nvl(avg.getAvgOther())), round1(nvl(avg.getAvgAdl())),
                monthly, recentHighRisk);
    }

    private static double nvl(Double v) { return v == null ? 0.0 : v; }
    private static double round1(double v) { return Math.round(v * 10) / 10.0; }
}
```

### 12.1 관리자 계정 등록
관리자(ADMIN) 계정은 회원가입으로 만들 수 없으며, 애플리케이션 시작 시 한 번 등록한다. 비밀번호는 BCrypt로 암호화해야 하므로 SQL 대신 `ApplicationRunner`에서 `PasswordEncoder`를 사용한다.

```java
@Component
@RequiredArgsConstructor
public class AdminInitializer implements ApplicationRunner {

    private final MemberRepository memberRepository;
    private final PasswordEncoder passwordEncoder;

    @Value("${app.admin.email}")
    private String adminEmail;

    @Value("${app.admin.password}")
    private String adminPassword;

    @Override
    @Transactional
    public void run(ApplicationArguments args) {
        if (!memberRepository.existsByEmail(adminEmail)) {
            memberRepository.save(Member.createAdmin(adminEmail, passwordEncoder.encode(adminPassword), "관리자"));
        }
    }
}
```

> `Member.createAdmin()`은 `role = ADMIN`, `status = ACTIVE`로 생성하는 정적 팩토리 메서드이다. 관리자 이메일·비밀번호는 `application.properties`(`app.admin.email`, `app.admin.password`)에서 관리한다.

## 13. 테이블 정의서

4장의 Entity를 MariaDB 물리 테이블 기준으로 정리한다. 테이블은 JPA(`ddl-auto`)가 Entity로부터 생성하며, 아래 표는 생성되는 스키마와 같아야 한다.

- **명명 규칙**: 테이블명은 복수형 snake_case, 컬럼명은 snake_case, 외래키는 `참조테이블 단수형_id`
- **공통 컬럼**: 모든 테이블은 `BaseEntity`를 상속하므로 `id`, `created_at`, `updated_at`을 가진다
- **문자셋**: `utf8mb4` / 엔진: `InnoDB`
- **Enum 컬럼**: `@Enumerated(EnumType.STRING)`으로 상수 이름을 문자열로 저장한다 (MariaDB에서는 `ENUM` 타입으로 생성)

> 기본값 칸의 "엔티티 초기값"은 DB DEFAULT가 아니라 Entity 필드 초기값·정적 팩토리에서 넣는 값이다. JPA가 INSERT 시 항상 값을 채우므로 DB DEFAULT는 두지 않는다.

### 13.3 키 및 인덱스

| 테이블 | 이름 | 종류 | 컬럼 | 용도 |
|---|---|---|---|---|
| members | PRIMARY | PK | id | |
| members | (UK) | UNIQUE | email | 로그인 ID 중복 방지, 이메일 조회 |
| surveys | (UK) | UNIQUE | exam_type | 검사 유형별 설문 1개 |
| questions | (FK) | FK | survey_id → surveys.id | 설문별 문항 조회 |
| survey_results | (FK) | FK | member_id → members.id | 회원별 결과 |
| survey_results | (FK) | FK | survey_id → surveys.id | 결과의 검사 유형 |
| survey_results | idx_survey_result_member_created | INDEX | member_id, created_at | 내 검사 이력 (최신순) |
| survey_results | idx_survey_result_created_at | INDEX | created_at | 기간 검색, 월별 추이 |
| survey_results | idx_survey_result_risk_level | INDEX | risk_level | 위험도 분포, 위험도 필터 |
| survey_results | idx_survey_result_active_created | INDEX | active, created_at | 대시보드·관리자 목록 (활성 결과 + 기간·정렬) |
