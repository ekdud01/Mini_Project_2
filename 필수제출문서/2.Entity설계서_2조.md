## 1. Entity 설계 개요

### 1.1 설계 목적
> JPA Entity 클래스 설계를 통해 객체-관계 매핑(ORM)을 정의하고,
> KDSQ 인지선별검사 비즈니스 도메인을 코드로 표현하여 데이터 무결성과 유지보수성이 용이한 시스템을 구축

### 1.2 설계 원칙
- **단일 책임 원칙**: 하나의 Entity는 하나의 비즈니스 개념만 표현
- **도메인별 패키지 분리**: 설문 도메인(`survey` 패키지: Survey, Question)과 결과 도메인(`result` 패키지: SurveyResult, Solution, ScoringService)을 분리. 결과 도메인만 설문 도메인을 참조한다.
- **소프트 삭제(Soft Delete) 적용**: 회원 탈퇴 시 UserStatus를 WITHDRAWN으로 변경하고, 관리자의 검사 결과 삭제는 `active = false`로 처리하여 검사 통계 및 이력 데이터의 정합성 유지
- **캡슐화 및 불변성**: 비즈니스 로직을 Entity 내부에 구현하고 무분별한 Setter 지양
- **연관관계 최소화**: 필요한 관계만 매핑하여 복잡도 감소
- **정규화 우선**: 검사 유형은 SurveyResult에 중복 저장하지 않고 연관된 Survey에서 조회

### 1.3 기술 스택
- **ORM 프레임워크**: Spring Data JPA [Version]
- **데이터베이스**: MariaDB [Version]
- **검증 프레임워크**: Bean Validation [Version]
- **감사 기능**: Spring Data JPA Auditing

### 4.1 Member Entity

#### 4.1.1 기본 정보
```java

@Getter

    // 필드 정의 (아래 상세 명세 참조)
```

#### 4.1.2 필드 상세 명세
| 필드명 | 데이터 타입 | 컬럼명 | 제약조건 | 설명 | 비즈니스 규칙 |
|--------|-------------|--------|----------|------|---------------|
| **id** | `Long` | `member_id` | PK, NOT NULL, AUTO_INCREMENT | 회원 고유 식별자 | 시스템 자동 생성 |
| **email** | `String` | `email` | UNIQUE, NOT NULL, LENGTH(100) | 이메일 | 로그인 ID 겸용 |
| **password** | `String` | `password` | NOT NULL, LENGTH(255) | 비밀번호 | BCrypt 암호화 |
| **name** | `String` | `name` | NOT NULL, LENGTH(50) | 환자명 | 필수 입력 |
| **gender** | `Gender` | `gender` | ENUM, NULL 허용 | 성별 | MALE, FEMALE. MEMBER는 회원가입 DTO에서 필수(@NotNull), ADMIN 계정은 환자 정보가 없으므로 null |
| **birthYear** | `Integer` | `birth_year` | NULL 허용 | 출생년도 | 통계 산출용. MEMBER는 회원가입 DTO에서 필수(@NotNull, 1900~현재연도), ADMIN 계정은 null |
| **status** | `UserStatus` | `status` | NOT NULL, ENUM | 회원 상태 | ACTIVE, WITHDRAWN (소프트 삭제). 본인 탈퇴와 관리자 탈퇴 처리 모두 WITHDRAWN |
| **role** | `Role` | `role` | NOT NULL, ENUM, DEFAULT('MEMBER') | 권한 | 회원가입 시 MEMBER, 관리자 계정은 초기 데이터로 ADMIN 등록 |
| **createdAt** | `LocalDateTime` | `created_at` | NOT NULL, 수정 불가 | 가입일 | BaseEntity 상속, JPA Auditing이 가입 시 자동 기록 (입력받지 않음) |

#### 4.1.3 연관관계 매핑
```java
// 1:N - 회원의 검사 결과 이력 목록
@OneToMany(mappedBy = "member", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
```

#### 4.1.4 비즈니스 메서드
```java
@Enumerated(EnumType.STRING)
@Column(nullable = false)
private Role role = Role.MEMBER;

/** 회원가입: 항상 MEMBER, ACTIVE로 생성 */
public static Member create(String email, String encodedPassword, String name,
                            Gender gender, Integer birthYear) {
    Member member = new Member();
    member.email = email;
    member.password = encodedPassword;
    member.name = name;
    member.gender = gender;
    member.birthYear = birthYear;
    member.status = UserStatus.ACTIVE;
    member.role = Role.MEMBER;
    return member;
}

/** 관리자 계정: 초기 데이터(AdminInitializer)에서만 호출. 환자 정보(성별·출생년도)는 없음 */
public static Member createAdmin(String email, String encodedPassword, String name) {
    Member admin = new Member();
    admin.email = email;
    admin.password = encodedPassword;
    admin.name = name;
    admin.status = UserStatus.ACTIVE;
    admin.role = Role.ADMIN;
    return admin;
}

/** 본인 탈퇴 / 관리자 탈퇴 처리 (소프트 삭제) */
public void withdraw() {
    this.status = UserStatus.WITHDRAWN;
}

/** 관리자 화면(ADM-04-1)에서만 호출. 이메일 중복 검사는 서비스에서 먼저 수행 */
public void updateInfo(String name, String email, Gender gender, Integer birthYear) {
    this.name = name;
    this.email = email;
    this.gender = gender;
    this.birthYear = birthYear;
}
```

#### 4.2.2 구현 코드 예시
```java
/**
 * 설문지 Entity (survey 패키지)
 */
@Entity
@Table(name = "surveys")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class Survey extends BaseEntity {

    @Enumerated(EnumType.STRING)
    @Column(name = "exam_type", nullable = false, unique = true)
    private ExamType examType;

    @Column(nullable = false, length = 100)
    private String title;

    @Column(columnDefinition = "TEXT")
    private String description;

    @OneToMany(mappedBy = "survey", cascade = CascadeType.ALL, fetch = FetchType.LAZY)
    @OrderBy("questionNumber ASC")
    private List<Question> questions = new ArrayList<>();
}

/**
 * 문항 Entity (survey 패키지)
 */
@Entity
@Table(name = "questions")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class Question extends BaseEntity {

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "survey_id", nullable = false)
    private Survey survey;

    @Column(name = "question_number", nullable = false)
    private Integer questionNumber;

    @Column(nullable = false, columnDefinition = "TEXT")
    private String content;
}
```

### 4.3 SurveyResult Entity

검사 1회당 결과 1건을 저장한다. KDSQ-P 0\~3점이면 1차 완료 시, KDSQ-P 4점 이상이면 KDSQ-C 완료 시 1·2차 점수를 합쳐 저장한다. 2차 대상자가 중간 이탈하면 저장하지 않는다.

#### 4.3.1 필드 상세 명세
| 필드명 | 데이터 타입 | 컬럼명 | 제약조건 | 설명 | 비즈니스 규칙 |
|--------|-------------|--------|----------|------|---------------|
| **id** | `Long` | `result_id` | PK, NOT NULL, AUTO_INCREMENT | 검사결과 고유 식별자 | 시스템 자동 생성 |
| **member** | `Member` | `member_id` | FK, NOT NULL | 검사 회원 | members 참조 |
| **survey** | `Survey` | `survey_id` | FK, NOT NULL | 마지막으로 완료한 설문 | 1차에서 종료 시 KDSQ-P, 2차까지 수행 시 KDSQ-C. 검사 유형은 `survey.examType`으로 조회 |
| **firstScore** | `Integer` | `first_score` | NOT NULL | 1차(KDSQ-P) 점수 | 0\~10점, 모든 결과에 존재 |
| **memoryScore** | `Integer` | `memory_score` | NULL 허용 | 기억력 영역 점수 | KDSQ-C (1~5번 합산), KDSQ-P로 끝난 결과는 null |
| **otherScore** | `Integer` | `other_score` | NULL 허용 | 기타 인지기능 영역 점수 | KDSQ-C (6~10번 합산), KDSQ-P로 끝난 결과는 null |
| **adlScore** | `Integer` | `adl_score` | NULL 허용 | 일상생활 수행능력 점수 | KDSQ-C (11~15번 합산), KDSQ-P로 끝난 결과는 null |
| **riskLevel** | `RiskLevel` | `risk_level` | NOT NULL, ENUM | 판정 등급 | Normal, Borderline, HighRisk |
| **active** | `Boolean` | `active` | NOT NULL, DEFAULT(true) | 활성 여부 | 관리자 삭제 시 false (소프트 삭제), 목록·통계에서 제외 |

> 영역별 점수를 nullable로 두는 이유: '검사를 하지 않음(null)'과 '0점'을 구분하고, 관리자 대시보드의 영역별 평균(`AVG`)이 null을 자동 제외하여 KDSQ-C 수행자만으로 계산되도록 하기 위함.

#### 4.3.2 구현 코드 예시
```java
/**
 * 검사결과 Entity (result 패키지)
 */
@Entity
@Table(name = "survey_results")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class SurveyResult extends BaseEntity {

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "member_id", nullable = false)
    private Member member;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "survey_id", nullable = false)
    private Survey survey; // 마지막으로 완료한 설문 (KDSQ-P 또는 KDSQ-C)

    @Column(name = "first_score", nullable = false)
    private Integer firstScore;

    @Column(name = "memory_score")
    private Integer memoryScore; // KDSQ-P로 끝난 결과는 null

    @Column(name = "other_score")
    private Integer otherScore;

    @Column(name = "adl_score")
    private Integer adlScore;

    @Enumerated(EnumType.STRING)
    @Column(name = "risk_level", nullable = false)
    private RiskLevel riskLevel;

    @Column(nullable = false)
    private Boolean active = true;

    // 비즈니스 메서드
    public ExamType getExamType() {
        return this.survey.getExamType();
    }

    /** KDSQ-C 총점. KDSQ-P로 끝난 결과는 null (저장하지 않고 계산) */
    public Integer getTotalScore() {
        if (getExamType() == ExamType.KDSQ_P) {
            return null;
        }
        return this.memoryScore + this.otherScore + this.adlScore;
    }

    /** 1차(KDSQ-P) 0~3점으로 검사가 끝난 경우 */
    public static SurveyResult createFirstOnly(Member member, Survey pSurvey, int firstScore) {
        if (firstScore >= 4) {
            throw new BusinessException(ErrorCode.KDSQ_C_REQUIRED);
        }
        SurveyResult result = new SurveyResult();
        result.member = member;
        result.survey = pSurvey;
        result.firstScore = firstScore;
        result.riskLevel = RiskLevel.Normal;
        return result;
    }

    /** 1차 4점 이상 후 2차(KDSQ-C)까지 완료한 경우 */
    public static SurveyResult createWithSecond(Member member, Survey cSurvey, int firstScore,
                                                int memoryScore, int otherScore, int adlScore) {
        if (firstScore < 4) {
            throw new BusinessException(ErrorCode.KDSQ_C_NOT_ALLOWED);
        }
        SurveyResult result = new SurveyResult();
        result.member = member;
        result.survey = cSurvey;
        result.firstScore = firstScore;
        result.memoryScore = memoryScore;
        result.otherScore = otherScore;
        result.adlScore = adlScore;
        result.riskLevel = result.evaluateRisk();
        return result;
    }

    private RiskLevel evaluateRisk() {
        if (getExamType() == ExamType.KDSQ_P) {
            return RiskLevel.Normal; // 1차에서 끝난 결과는 0~3점만 저장되므로 항상 정상
        }
        return (getTotalScore() <= 5) ? RiskLevel.Borderline : RiskLevel.HighRisk;
    }

    /** 관리자 삭제 (소프트 삭제) */
    public void deactivate() {
        this.active = false;
    }
}
```

#### 4.3.3 채점 서비스 (ScoringService)
```java
/**
 * 제출된 답변을 채점하여 SurveyResult를 생성 (result 패키지)
 * - 프론트엔드의 1차 합계는 화면 이동용이며, 최종 채점·판정은 이 서비스가 담당한다.
 */
@Service
@RequiredArgsConstructor
public class ScoringService {

    /** KDSQ-P 5문항 합계 */
    public int scoreFirst(List<AnswerDto> firstAnswers) {
        validateCount(firstAnswers, 5);
        return sum(firstAnswers, 1, 5);
    }

    /** KDSQ-C 15문항 영역별 합계: [기억력(1~5), 기타 인지(6~10), 일상생활(11~15)] */
    public int[] scoreSecond(List<AnswerDto> answers) {
        validateCount(answers, 15);
        return new int[] { sum(answers, 1, 5), sum(answers, 6, 10), sum(answers, 11, 15) };
    }
    // sum(): questionNumber 범위의 score 합산, validateCount(): 개수 불일치 시 INVALID_ANSWER_COUNT
}
```

### 4.4 Solution Entity

#### 4.4.1 필드 상세 명세
| 필드명 | 데이터 타입 | 컬럼명 | 제약조건 | 설명 | 비즈니스 규칙 |
|--------|-------------|--------|----------|------|---------------|
| **id** | `Long` | `solution_id` | PK, NOT NULL, AUTO_INCREMENT | 솔루션 식별자 | 시스템 자동 생성 |
| **riskLevel** | `RiskLevel` | `risk_level` | NOT NULL, ENUM | 대상 위험도 등급 | Borderline, HighRisk |
| **title** | `String` | `title` | NOT NULL, LENGTH(100) | 솔루션 제목 | 필수 입력 |
| **content** | `String` | `content` | NOT NULL, TEXT | 솔루션 권고사항 내용 | 필수 입력 |

> SurveyResult와 FK로 연결하지 않고, 결과 상세 조회 시 `riskLevel`로 조회하여 응답의 `solutions`에 포함한다.

#### 4.4.2 구현 코드 예시
```java
/**
 * 솔루션 안내 Entity (result 패키지)
 */
@Entity
@Table(name = "solutions")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
```

## 6. 연관관계 매핑 전략

### 6.1 연관관계 매핑 규칙
| 관계 유형 | 기본 전략 | 이유 | 예외 상황 |
|----------|-----------|------|-----------|
| **@ManyToOne** | LAZY | 성능 최적화 | 필수 조회 데이터는 EAGER |
| **@OneToMany** | LAZY | N+1 문제 방지 | 소량 데이터는 EAGER |
| **@OneToOne** | LAZY | 일관성 유지 | 항상 함께 조회하는 경우 EAGER |
| **@ManyToMany** | 사용 금지 | 복잡성 증가 | 중간 테이블로 대체 |

### 6.2 연관관계 요약
| 관계 | 매핑 | 설명 |
|------|------|------|
| Member 1:N SurveyResult | `SurveyResult.member` (@ManyToOne) / `Member.surveyResults` (@OneToMany) | 회원별 검사 이력 |
| Survey 1:N Question | `Question.survey` (@ManyToOne) / `Survey.questions` (@OneToMany) | 설문별 문항 |
| Survey 1:N SurveyResult | `SurveyResult.survey` (@ManyToOne, 단방향) | 결과가 마지막으로 완료한 설문을 참조. 설문 도메인은 결과를 알지 못하므로 Survey 쪽 컬렉션은 두지 않음 |

## 12. 초기 데이터

### 12.1 관리자 계정 등록
관리자(ADMIN) 계정은 회원가입으로 만들 수 없으며, 애플리케이션 시작 시 한 번 등록한다. 비밀번호는 BCrypt로 암호화해야 하므로 SQL 대신 `ApplicationRunner`에서 `PasswordEncoder`를 사용한다.

```java
@Component
@RequiredArgsConstructor
public class AdminInitializer implements ApplicationRunner {

    private final MemberRepository memberRepository;
    private final PasswordEncoder passwordEncoder;

    @Value("${app.admin.email}")
    private String adminEmail;

    @Value("${app.admin.password}")
    private String adminPassword;

    @Override
    @Transactional
    public void run(ApplicationArguments args) {
        if (!memberRepository.existsByEmail(adminEmail)) {
            memberRepository.save(Member.createAdmin(adminEmail, passwordEncoder.encode(adminPassword), "관리자"));
        }
    }
}
```

> `Member.createAdmin()`은 `role = ADMIN`, `status = ACTIVE`로 생성하는 정적 팩토리 메서드이다. 관리자 이메일·비밀번호는 `application.properties`(`app.admin.email`, `app.admin.password`)에서 관리한다.

### 12.2 설문·문항·솔루션 데이터
Survey(KDSQ-P, KDSQ-C), Question(5문항, 15문항), Solution(Borderline, HighRisk) 데이터는 `data.sql`로 등록한다.
