## 1. 컴포넌트 개요

### 1.1 컴포넌트 목록

| 화면 ID | 화면명 | 페이지 컴포넌트 | URL | 권한 |
|---|---|---|---|---|
| SCR-01 | 로그인 | `LoginPage` | `/login` | 공개 |
| SCR-02 | 회원가입 | `RegisterPage` | `/register` | 공개 |
| SCR-03 | KDSQ-P 1차 검사 | `SurveyPage` (`type="P"`) | `/surveys/p` | 로그인 필요 |
| SCR-04 | KDSQ-C 2차 검사 | `SurveyPage` (`type="C"`) | `/surveys/c` | 로그인 필요 |
| SCR-05 | 검사 결과 | `ResultPage` | `/results/:resultId` | 로그인 필요 |
| SCR-06 | 마이페이지 | `MyPage` | `/mypage` | 로그인 필요 |

> SCR-03과 SCR-04는 화면 구성이 동일하여 `SurveyPage` 하나로 만들고 `type`으로 구분

### 1.2 목적 및 역할

- **주요 목적**: 회원가입·로그인 후 KDSQ-P(1차) → KDSQ-C(2차) 인지선별검사를 진행하고, 결과와 검사 이력을 조회하는 사용자 화면 구현
- **위치**: `src/pages/`(페이지), `src/components/`(레이아웃·공통)
- **컴포넌트 유형**: 페이지 / 레이아웃 / 기능 / 공통 컴포넌트

### 1.3 기능 요구사항

- [ ] 로그인·회원가입 (입력 검증, 401 실패 문구, 409 이메일 중복 안내)
- [ ] KDSQ-P 5문항 검사 → 1차 합계 0–3점이면 결과 제출 후 결과 화면 / 4–10점이면 제출 없이 1차 답변을 보관하고 `/surveys/c`로 이동 (2차 화면 상단에 안내 문구)
- [ ] KDSQ-C 15문항 검사 → 1·2차 답변을 함께 제출 → 서버 채점 결과 화면
- [ ] `/surveys/c`에 1차 답변 없이 들어오면 `/surveys/p`로 이동
- [ ] 검사 결과 표시 (총점·판정, KDSQ-C는 영역별 점수 + 관리 안내(`solutions`))
- [ ] 마이페이지 (회원정보 조회 전용, 검사 이력, 점수 추이, 이력 없음 안내, 회원 탈퇴)
- [ ] 로딩 / 오류 / 빈 데이터 상태 처리, 비로그인 접근 시 `/login` 이동

> 점수 채점과 위험도 판정은 서버(results)가 담당한다. 프론트는 1차 합계로 2차 진행 여부만 판단하고, 결과는 서버 응답 값을 그대로 표시한다.

## 2. 컴포넌트 구조 설계

### 2.1 컴포넌트 트리

```
UserLayout                              ← 공통 레이아웃 (Header + Outlet + Footer)
  ├── LoginPage                         ← 로그인 API 호출, 로딩·실패 문구·안내 상태
  │     └── LoginForm                   ← (Props: onSubmit, isLoading, errorMessage) 입력값 상태 소유·검증
  ├── RegisterPage                      ← 회원가입 API 호출, 로딩 상태, 서버 오류를 필드 오류로 변환
  │     └── RegisterForm                ← (Props: onSubmit, isLoading) 입력값·오류 상태 소유·검증
  └── ProtectedRoute                    ← 비로그인 시 /login 이동
        ├── SurveyPage                  ← 상태 소유, 문항 조회·결과 제출 (P/C 공용)
        │     ├── SurveyIntro           ← (Props: description, onStart) 1차 검사 시작 안내 + [검사 시작하기] (type="P"일 때만)
        │     │     └── SurveyHeader    ← 시작 안내 화면용 제목으로 재사용
        │     ├── SurveyHeader          ← (Props: type, title, description) 단계 배지·검사명·(2차) 진행 안내·안내 문구
        │     ├── ProgressBar           ← (Props: current, total) 진행률
        │     ├── QuestionCard          ← (Props: question) 문항 표시 — 내부에 문항 번호·내용 표시 (UI 설계서의 QuestionNumber·QuestionContent 요소)
        │     ├── AnswerOptions         ← (Props: value, onChange, invalid) 답변 선택
        │     ├── PreviousButton        ← (Props: isDisabled, onClick) 이전 문항
        │     ├── NextButton            ← (Props: onClick) 다음 문항
        │     └── SubmitButton          ← (Props: isSubmitting, onClick) 마지막 문항 제출
        ├── ResultPage                  ← 상태 소유, 결과 조회 API 호출
        │     ├── ResultHeader          ← (Props: examType) 결과 제목 ("KDSQ-C 검사 결과")
        │     ├── ExamDate              ← (Props: date) 검사일시
        │     ├── ResultStatus          ← (Props: riskLevel) 정상/주의/위험 판정 문구·보조 설명
        │     ├── TotalScore            ← (Props: score, maxScore, examType, riskLevel) 총점·판정 배지·판정 기준 막대
        │     ├── ScoreSummary          ← (Props: memoryScore, otherScore, adlScore) 영역별 점수 (KDSQ-C)
        │     ├── Recommendation        ← (Props: solutions) 관리·추가 검진 안내 (KDSQ-C)
        │     ├── HistoryButton         ← (Props: onClick) /mypage 이동
        │     └── HomeButton            ← (Props: onClick) /surveys/p 이동
        └── MyPage                      ← 상태 소유, 회원정보·이력 조회 API 호출
              ├── MyPageSectionNav      ← (Props: hasHistory) 모바일 목차 (회원 정보·검사 결과 추이·검사 이력)
              ├── ProfileCard           ← (Props: me) 회원정보 조회
              │     └── ReadOnlyNotice  ← 수정 불가 안내
              ├── ExamTrendChart        ← (Props: results, totalElements) 검사 결과 추이 (Chart.js)
              ├── ExamHistoryTable      ← (Props: results, page, pageSize, onPageChange, onDetail) 검사 이력 목록
              │     ├── ExamHistoryCard ← (Props: result, onDetail) 모바일 이력 카드
              │     └── RiskBadge       ← (Props: riskLevel) 판정 배지
              ├── EmptyHistory          ← 이력 없음 안내 + 검사 시작 링크 (<Link to="/surveys/p">)
              └── WithdrawDialog        ← (Props: open, isWithdrawing, errorMessage, onOpenChange, onConfirm, children) 탈퇴 확인
                    └── WithdrawButton  ← children으로 전달, DialogTrigger가 대화상자를 엶
```

> 로딩·오류 표시는 공통 `LoadingSpinner`(`components/common`)와 shadcn `Alert`(`@/components/ui/alert`)를 사용합니다. `components/common/Alert.jsx`는 따로 만들지 않습니다. 컴포넌트 이름(`Exam*`)은 화면 용어('검사')를 따르며, 데이터 타입은 `SurveyResult`를 사용합니다.

## 3. Props 설계

### 3.1 Props 인터페이스

| 컴포넌트 | Props명 | 타입 | 필수여부 | 기본값 | 설명 |
|---|---|---|---|---|---|
| `LoginForm` | `onSubmit` | `(email, password) => void` | 필수 | — | 검증 통과 후 호출 |
| | `isLoading` | `boolean` | 선택 | `false` | 로그인 중 버튼 비활성화 |
| | `errorMessage` | `string` | 선택 | `''` | 로그인 실패 문구 |
| `SurveyPage` | `type` | `'P' \| 'C'` | 필수 | — | 검사 종류 |

### 3.2 Props 검증 (PropTypes)

프로젝트는 JavaScript(JSX)로 작성하므로 TypeScript 대신 `prop-types` 라이브러리로 Props를 검증한다. 3.1 표의 타입·필수여부·기본값을 그대로 코드로 옮기며, 개발 모드에서 잘못된 Props가 전달되면 브라우저 콘솔에 경고가 출력된다.

**작성 규칙**

| 규칙 | 적용 방법 |
|---|---|
| 모든 컴포넌트에 선언 | Props를 받는 컴포넌트는 `Component.propTypes`를 반드시 작성한다 |
| 필수 Props | 3.1 표의 "필수"는 `.isRequired`를 붙인다 |
| 기본값 | 3.1 표의 기본값은 함수 매개변수 기본값으로 지정한다 (`{ isLoading = false }`) |
| 고정 값 목록 | `'P' \| 'C'`, 판정 등급처럼 값이 정해진 Props는 `PropTypes.oneOf([...])` |
| 도메인 객체 | `Question`, `SurveyResult` 등은 `src/types/propTypes.js`에 `PropTypes.shape`로 한 번만 정의하고 가져다 쓴다 |
| 콜백 | `onSubmit`, `onChange` 등 함수 Props는 `PropTypes.func` |

**공통 shape 정의 (`src/types/propTypes.js`)**

```jsx
import PropTypes from 'prop-types';

export const RiskLevelType = PropTypes.oneOf(['Normal', 'Borderline', 'HighRisk']);

export const QuestionShape = PropTypes.shape({
  id: PropTypes.number.isRequired,
  questionNumber: PropTypes.number.isRequired,
  content: PropTypes.string.isRequired,
});

export const SolutionShape = PropTypes.shape({
  id: PropTypes.number.isRequired,
  title: PropTypes.string.isRequired,
  content: PropTypes.string.isRequired,
});

export const SurveyResultShape = PropTypes.shape({
  id: PropTypes.number.isRequired,
  examType: PropTypes.oneOf(['KDSQ_P', 'KDSQ_C']).isRequired,
  firstScore: PropTypes.number.isRequired,
  memoryScore: PropTypes.number,      // KDSQ-P로 끝나면 null
  otherScore: PropTypes.number,
  adlScore: PropTypes.number,
  totalScore: PropTypes.number,
  riskLevel: RiskLevelType.isRequired,
  createdAt: PropTypes.string.isRequired,
  solutions: PropTypes.arrayOf(SolutionShape),
});

export const MemberShape = PropTypes.shape({
  name: PropTypes.string.isRequired,
  email: PropTypes.string.isRequired,
  gender: PropTypes.oneOf(['MALE', 'FEMALE']).isRequired,
  birthYear: PropTypes.number.isRequired,
});
```

### 4.1 상태 위치 결정 근거

### 4.3 Zustand 스토어

| 스토어 | 상태 | 액션 |
|---|---|---|

(`authStore`가 다른 스토어를 직접 import하지 않으므로 순환 참조가 생기지 않는다)

### 5.3 에러 처리

에러 응답은 `{ success: false, error: { code, message } }` 형식이며, HTTP 상태가 아니라 `error.code`로 분기한다. 화면에서는 공용 유틸 `utils/apiError.js`를 사용한다.

| 함수 | 역할 |
|---|---|
| `getErrorCode(error)` | 응답의 `error.code` 반환 (없으면 `undefined`) |
| `getFieldErrors(error)` | `error.fields`(`[{ field, message }]`)를 `{ field: message }` 객체로 변환 |
| `getErrorMessage(error, messages, fallback)` | 서버 응답이 없으면 네트워크 오류 문구, 있으면 `messages[code]`, 없으면 기본 문구("일시적인 오류입니다. 잠시 후 다시 시도해주세요") |

| error.code | 처리 |
|---|---|
| `VALIDATION_ERROR` | `error.fields`(`[{ field, message }]`)를 `{ field: message }` 객체로 바꿔 `RegisterForm.errors`에 넣고 각 입력칸 아래에 표시 |
| `INVALID_CREDENTIALS` | 로그인: "이메일 또는 비밀번호를 확인해주세요" |
| `ACCESS_TOKEN_EXPIRED` | axios 응답 인터셉터에서 `POST /api/auth/reissue` 후 원래 요청 1회 재시도 |
| `INVALID_REFRESH_TOKEN` | 재발급 실패. 다시 재발급을 시도하지 않고 `authStore.clear({ reason: '다시 로그인해주세요' })` 후 `/login` (로그인 화면에 사유 표시) |
| `UNAUTHORIZED` | `authStore.clear({ reason: '다시 로그인해주세요' })` 후 `/login` |
| `DUPLICATE_EMAIL` | "이미 사용 중인 이메일입니다" (이메일 입력칸 아래 표시) |
| `MEMBER_WITHDRAWN` | 로그인: "이용할 수 없는 계정입니다" (탈퇴 회원) |
| `KDSQ_C_NOT_ALLOWED`, `KDSQ_C_REQUIRED` | "1차 검사부터 다시 진행해주세요" 안내 후 `clearPendingFirstAnswers()`, `/surveys/p` 이동 |
| `INVALID_ANSWER_COUNT` | "모든 문항에 답해주세요" |
| `RESULT_NOT_FOUND` 및 그 외 (500, 네트워크) | 오류 메시지 + 재시도 |

### 5.4 개발 서버 연결 및 공통 설정

React 개발 서버(Vite, 5173 포트)와 Spring 서버(8080 포트)는 주소가 달라 그대로 호출하면 CORS 오류가 난다. Vite 프록시로 `/api` 요청을 8080으로 넘겨, 브라우저에서는 같은 주소로 보이게 한다. (Spring에 CORS 설정 불필요)

```js
// vite.config.js
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import path from 'path';

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { '@': path.resolve(__dirname, './src') },   // import '@/components/...'
  },
  server: {
    port: 5173,
    proxy: {
      '/api': { target: 'http://localhost:8080', changeOrigin: true },
    },
  },
});
```

```js
// src/api/axiosInstance.js
const axiosInstance = axios.create({
  baseURL: '/api',                  // 프록시를 거쳐 http://localhost:8080/api 로 전달
  headers: { 'Content-Type': 'application/json' },
});
// 요청 인터셉터: authStore.accessToken → Authorization: Bearer {토큰}
// 응답 인터셉터: 5.3 에러 처리 (ACCESS_TOKEN_EXPIRED → 재발급 후 1회 재시도)
```

| 항목 | 규칙 |
|------|------|
| API 주소 | 코드에서는 항상 `/api/...` 상대 경로로 호출하고 `http://localhost:8080`을 직접 쓰지 않는다 |
| 경로 별칭 | `@/` = `src/` (shadcn/ui 기본 설정과 같음) |
| 날짜 표시 | 서버는 한국 시간 `"2026-09-24T10:30:00"` 형식으로 보낸다 (REST API 설계서 2.5). 결과 화면 검사일시는 `utils/date.js`의 `formatDateTime()`으로 `2026-09-24 10:30`, 마이페이지 이력 표는 `formatDateOnly()`로 `2026-09-24`, 그래프 축은 `formatDate()`로 `09.24` 형태로 표시한다. 문자열에 시간대가 없으므로 `new Date()` 변환 시 브라우저 시간(한국)으로 해석된다 |

### 5.5 차트 (Chart.js)

마이페이지 검사 결과 추이 그래프는 Chart.js 4(`chart.js`)로 그린다. 관리자 회원 상세 추이 차트와 같은 라이브러리·판정색을 써서 두 화면의 모양을 맞춘다 (PR #63에서 Recharts → Chart.js).

- 세로축은 점수가 아니라 **판정 단계**(정상 0 / 주의 1 / 위험 2)이고, 위로 갈수록 위험도가 높다. 점마다 점수를 알약 모양 글자로 함께 표시한다 (1차 10점, 2차 30점 만점)
- 가로축은 검사일(`MM.DD`, 연도가 바뀌는 검사에만 둘째 줄에 연도), 오래된 검사가 왼쪽이고 가장 최근 검사를 강조한다
- 검사가 많아 화면보다 넓으면 가로 스크롤, 처음에는 가장 최근 검사가 보이게 한다
- `results`가 0건이면 그래프를 그리지 않는다 (`return null`)

```jsx
// src/pages/MyPage/components/ExamTrendChart.jsx (요약)
import { Chart, LineController, LineElement, PointElement, CategoryScale, LinearScale, Tooltip } from 'chart.js';
import { toTrendData } from '../history';

Chart.register(LineController, LineElement, PointElement, CategoryScale, LinearScale, Tooltip);

function ExamTrendChart({ results = [], totalElements }) {
  const data = useMemo(() => toTrendData(results), [results]);   // 오래된 순, level(0~2)·score·label 계산
  const canvasRef = useRef(null);

  useEffect(() => {
    if (!data.length) return;
    const chart = new Chart(canvasRef.current, {
      type: 'line',
      data: { labels: data.map((d) => d.label), datasets: [{ data: data.map((d) => d.level) }] },
      options: {
        maintainAspectRatio: false,
        scales: { y: { min: -0.3, max: 2.3 } },                  // 판정 단계 0·1·2
      },
    });
    return () => chart.destroy();                                // 데이터가 바뀌거나 화면을 떠나면 정리
  }, [data]);

  if (!data.length) return null;
  return <canvas ref={canvasRef} />;
}

ExamTrendChart.propTypes = { results: PropTypes.arrayOf(SurveyResultShape), totalElements: PropTypes.number };
export default memo(ExamTrendChart);
```

**라우터 코드 스플리팅 예시 (`src/App.jsx`)**

```jsx
import { lazy, Suspense } from 'react';
import { BrowserRouter, Routes, Route, Navigate } from 'react-router-dom';
import UserLayout from '@/components/layout/UserLayout';
import ProtectedRoute from '@/components/common/ProtectedRoute';
import LoadingSpinner from '@/components/common/LoadingSpinner';

// 페이지 단위로 번들을 나눔 (해당 URL에 처음 들어갈 때 다운로드)
const LoginPage = lazy(() => import('@/pages/Login'));
const RegisterPage = lazy(() => import('@/pages/Register'));
const SurveyPage = lazy(() => import('@/pages/Survey'));
const ResultPage = lazy(() => import('@/pages/Result'));
const MyPage = lazy(() => import('@/pages/MyPage'));

export default function App() {
  return (
    <BrowserRouter>
      <Suspense fallback={<LoadingSpinner />}>
        <Routes>
          <Route element={<UserLayout />}>
            <Route path="/login" element={<LoginPage />} />
            <Route path="/register" element={<RegisterPage />} />
            <Route element={<ProtectedRoute />}>
              <Route path="/surveys/p" element={<SurveyPage type="P" />} />
              <Route path="/surveys/c" element={<SurveyPage type="C" />} />
              <Route path="/results/:resultId" element={<ResultPage />} />
              <Route path="/mypage" element={<MyPage />} />
            </Route>
            <Route path="*" element={<Navigate to="/login" replace />} />
          </Route>
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}
```

> 페이지를 불러오는 동안 `Suspense`의 `fallback`으로 공통 `LoadingSpinner`를 보여준다. 공통 컴포넌트(`Header`, `ProtectedRoute`)와 스토어는 모든 화면에서 쓰므로 나누지 않는다.
