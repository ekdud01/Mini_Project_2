- **검토자**: 서다영

---

# 1. API 설계 개요

## 1.1 설계 목적
> KDSQ-P(1차) 및 KDSQ-C(2차) 인지선별검사, 회원 관리, 검사 결과 및 맞춤 솔루션 조회 기능을 RESTful API로 제공

## 1.2 설계 원칙
- **RESTful 아키텍처**: HTTP 메서드와 상태 코드의 올바른 사용
- **일관성**: 모든 API 엔드포인트에서 동일한 규칙 적용  
- **버전 관리**: URL 경로를 통한 버전 구분 
- **보안**: JWT 기반 인증
- **성능**: 검사 결과 및 이력 조회를 고려한 페이지네이션
- **문서화**: JSON 기반 요청/응답

## 1.3 기술 스택
- **Framework**: Spring Boot 4.0.8
- **인증**: JWT(JSON Web Token)
- **직렬화**: JSON
- **API 문서**: OpenAPI 3.0(Swagger)
- **DB**: MariaDB
- **ORM**: Spring Data JPA

# 2. API 공통 규칙

## 2.1 URL 설계 규칙

| 규칙 | 설명 | 좋은 예 | 나쁜 예 |
|------|------|------|-------|
| **명사 사용** | 동사가 아닌 명사로 리소스를 표현 | `/api/members` | `/api/getMembers` |
| **복수형 사용** | 컬렉션은 복수형으로 표현 | `/api/surveys` | `/api/survey`| 
| **계층 구조** | 연관된 리소스 간의 관계를 URL로 표현 | `/api/members/{memberId}/results` | `/api/getMemberResults` |
| **소문자 사용** | URL은 소문자로 일관되게 표현 | `/api/members` | `/api/Members` |
| **동작 표현** | 생성·조회·수정·삭제 등의 동작은 HTTP 메서드로 구분 | `POST /api/members` | `/api/createMember` |


## 2.2 HTTP 메서드 사용 규칙 

| 메서드 | 용도 | 멱등성 | 안전성 | 예시 |
| ----- | ---- | ---- | ---- | ---- |
| **GET** | 리소스 조회 | ✅ | ✅ | `GET /api/members` |
| **POST** | 리소스 생성 및 검사 결과 제출 | ❌ | ❌ | `POST /api/results` |
| **PUT** | 리소스 전체 수정 | ✅ | ❌ | `PUT /api/members/{memberId}` |
| **PATCH** | 리소스 부분 수정 및 상태 변경 | ❌ | ❌ | `PATCH /api/members/{memberId}` |
| **DELETE** | 리소스 삭제 | ✅ | ❌ | `DELETE /api/members/{memberId}` |


## 2.3 HTTP 상태 코드 가이드 

| 코드 | 상태 | 설명 | 사용 예시 |
| ---- | ---- | ---- | ---- |
| **200** | OK | 요청 성공 (응답 데이터 포함) | GET 조회 또는 PUT/PATCH 수정 성공 |
| **201** | Created | 리소스 생성 성공 | POST 요청 성공 |
| **204** | No Content | 요청 성공 (응답 데이터 없음) | DELETE 요청 성공 |
| **400** | Bad Request | 잘못된 요청 | 필수값 누락 또는 요청값 검증 실패 |
| **401** | Unauthorized | 인증 필요 | 로그인하지 않았거나 토큰이 없거나 만료된 경우 |
| **403** | Forbidden | 접근 권한 없음 | 허용되지 않은 리소스 접근 |
| **404** | Not Found | 리소스를 찾을 수 없음 | 존재하지 않는 회원 또는 검사 결과 조회 |
| **409** | Conflict | 리소스 상태 충돌 | 이미 가입된 이메일로 회원가입 시도 |
| **422** | Unprocessable Entity | 비즈니스 규칙 위반 | 검사 결과의 점수 범위 또는 검사 진행 규칙 위반 |
| **500** | Internal Server Error | 서버 내부 오류 | 예기치 않은 서버 오류 |


## 2.4 공통 요청 헤더

```
Content-Type: application/json
Accept: application/json
Authorization: Bearer {JWT_TOKEN}
```

# 3. 인증 및 권한 관리 

## 3.1 JWT 토큰 기반 인증

### 3.1.1 회원가입 API

```yaml
POST /api/members
Content-Type: application/json

Request Body:
{
  "email": "user@example.com",
  "password": "password123!",
  "name": "김철수",
  "gender": "MALE",
  "birthYear": 1955
}

Validation Rules:
- email: 필수, 이메일 형식, 중복 불가
- password: 필수, BCrypt 암호화 저장
- name: 필수
- gender: MALE 또는 FEMALE
- birthYear: 필수

Response (201 Created):
{
  "success": true,
  "data": {
    "id": 1,
    "email": "user@example.com",
    "name": "김철수",
    "gender": "MALE",
    "birthYear": 1955,
    "status": "ACTIVE"
  },
  "message": "회원가입이 완료되었습니다"
}
```

### 3.1.2 로그인 API

```yaml
POST /api/auth/login
Content-Type: application/json

Request Body:
{
  "email": "user@example.com",
  "password": "password123!"
}

Response (200 OK):
{
  "success": true,
  "data": {
    "accessToken": "JWT_ACCESS_TOKEN",
    "refreshToken": "JWT_REFRESH_TOKEN",
    "tokenType": "Bearer",
    "expiresIn": 3600
  },
  "message": "로그인이 성공하였습니다"
}

Response (401 Unauthorized):
{
  "success": false,
  "error": {
    "code": "INVALID_CREDENTIALS",
    "message": "이메일 또는 비밀번호가 올바르지 않습니다"
  }
}
```

### 3.1.3 로그아웃 API

```yaml
POST /api/auth/logout
Authorization: Bearer {JWT_TOKEN}

Response (204 No Content)
```

## 3.2 권한 레벨 정의

| 역할 | 권한 | 비고 |
|------|------|------|
| **MEMBER** | 회원가입, 로그인, 본인 정보 조회/수정, 검사 응시, 본인 검사 결과/이력 조회 | 일반 사용자 |

## 4.3 검사 및 결과 API

### 4.3.1 KDSQ-P 검사 제출

```yaml
POST /api/exam-results
Content-Type: application/json
Authorization: Bearer {JWT_TOKEN}
Required Role: MEMBER

Request Body:
{
  "examType": "KDSQ_P",
  "answers": [
    {
      "questionId": 1,
      "score": 0
    },
    {
      "questionId": 2,
      "score": 1
    }
  ]
}

Business Rules:
- KDSQ-P는 5문항 검사
- 점수를 자동 합산
- 0~3점: Normal
- 4~10점: Borderline 판정 후 KDSQ-C 추가 검사 진행
- 검사 결과는 회원별 이력으로 저장

Response (201 Created):
{
  "success": true,
  "data": {
    "id": 101,
    "examType": "KDSQ_P",
    "pScore": 4,
    "memoryScore": 0,
    "otherScore": 0,
    "adlScore": 0,
    "riskLevel": "Borderline",
    "nextExamType": "KDSQ_C",
    "createdAt": "2026-09-24T10:30:00Z"
  },
  "message": "1차 검사가 완료되었습니다"
}
```

### 4.3.2 KDSQ-C 검사 제출

```yaml
POST /api/exam-results
Content-Type: application/json
Authorization: Bearer {JWT_TOKEN}
Required Role: MEMBER

Request Body:
{
  "examType": "KDSQ_C",
  "pScore": 4,
  "answers": [
    {
      "questionId": 6,
      "score": 1
    }
  ]
}

Business Rules:
- KDSQ-C는 15문항 검사
- 1~5번: memoryScore
- 6~10번: otherScore
- 11~15번: adlScore
- 총점 0~5점: Borderline
- 총점 6~30점: HighRisk
- 선행 KDSQ-P 점수는 pScore로 보관

Response (201 Created):
{
  "success": true,
  "data": {
    "id": 102,
    "examType": "KDSQ_C",
    "pScore": 4,
    "memoryScore": 2,
    "otherScore": 2,
    "adlScore": 3,
    "totalScore": 7,
    "riskLevel": "HighRisk",
    "createdAt": "2026-09-24T10:35:00Z"
  },
  "message": "2차 검사가 완료되었습니다"
}
```

# 5. 에러 코드 및 처리

## 5.1 표준 에러 코드 정의

| 코드 | HTTP 상태 | 설명 |
|------|-----------|------|
| **VALIDATION_ERROR** | 400 | 입력값 검증 실패 |
| **INVALID_CREDENTIALS** | 401 | 이메일 또는 비밀번호 오류 |
| **TOKEN_EXPIRED** | 401 | JWT 토큰 만료 |
| **ACCESS_DENIED** | 403 | 접근 권한 없음 |
| **RESOURCE_NOT_FOUND** | 404 | 요청 리소스 없음 |
| **DUPLICATE_EMAIL** | 409 | 이미 사용 중인 이메일 |
| **BUSINESS_RULE_VIOLATION** | 422 | 비즈니스 규칙 위반 |
| **INTERNAL_SERVER_ERROR** | 500 | 서버 내부 오류 |

## 5.2 도메인별 에러 코드

| 코드 | 설명 |
|------|------|
| **MEMBER_NOT_FOUND** | 회원을 찾을 수 없음 |
| **MEMBER_WITHDRAWN** | 탈퇴 회원 |
| **SURVEY_NOT_FOUND** | 설문지를 찾을 수 없음 |
| **QUESTION_NOT_FOUND** | 문항을 찾을 수 없음 |
| **EXAM_RESULT_NOT_FOUND** | 검사 결과를 찾을 수 없음 |
| **INVALID_EXAM_TYPE** | 지원하지 않는 검사 유형 |
| **INVALID_ANSWER_COUNT** | 문항 수가 검사 유형과 일치하지 않음 |
| **KDSQ_C_NOT_ALLOWED** | KDSQ-P 선행 조건 없이 KDSQ-C 진행 시도 |
| **SOLUTION_NOT_FOUND** | 해당 위험도 솔루션을 찾을 수 없음 |

# 8. 마무리

## 8.1 주요 포인트 요약

1. **회원 관리**: 이메일 기반 회원가입/로그인 및 회원 정보 관리
2. **검사 관리**: KDSQ-P 5문항 → 필요 시 KDSQ-C 15문항 진행
3. **결과 관리**: 점수 자동 산출, 위험도 판정, 검사 이력 저장
4. **솔루션 제공**: Borderline/HighRisk 결과에 따른 정보 제공
5. **통계 제공**: 개인 검사 추이 및 전체 사용자 통계의 기반 마련
6. **인증/보안**: JWT 기반 인증 및 본인/관리자 접근 제어

## 8.2 1차 초안에서 추후 확정할 항목

- 관리자 인증/권한의 구체적인 구현 방식
- KDSQ 답변 점수의 허용 범위 및 문항별 점수 체계
- KDSQ-C 결과 저장 방식(별도 결과 생성 vs KDSQ-P 결과와 연결/업데이트)
- 통계 API의 상세 지표
- 솔루션과 검사 결과의 실제 매핑 방식
- Refresh Token 재발급 API
- API 공통 응답 DTO의 최종 구조
