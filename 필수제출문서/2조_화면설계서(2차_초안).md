## 1. 문서 개요

### 1.1 화면 설계 목표

본 시스템은 사용자가 로그인 후 KDSQ 기반 인지선별검사를 단계적으로 수행하고, 검사 결과와 과거 검사 이력을 확인할 수 있도록 구성한다. 통계 기능은 개인(사용자) 대상이 아닌 관리자(병원 관계자) 대상으로 제공한다.

### 1.2 시스템 구성

- **User 프론트엔드**: React SPA
- **Admin 페이지**: Spring MVC + Thymeleaf 서버사이드 렌더링 (React 미사용, 별도 아키텍처, **1인 개발**)
- **DB**: 병원 로컬 DB. 개발사는 데이터 접근 없이 유지보수만 수행
- **권한 3그룹**: 개인(User) / 병원관계자(Admin) / 개발자(유지보수 전용, 데이터 접근 없음)
- **로그인 필수**, **회원정보 수정은 User 불가 / Admin 가능**, **회원 탈퇴는 즉시 삭제(1단계)**

### 1.3 핵심 흐름

```text
회원가입 (로그인 필수)
   ↓
로그인
   ↓
검사 메인
   ↓
KDSQ-P (1차) 5문항 검사
   ↓
firstScore 산출 (10점 만점)
   ├── 0~3점  → 정상 → 결과 화면 → 종료
   │
   └── 4~10점 → 주의 → KDSQ-C (2차) 상세검사로 전환
                                ↓
                      15문항 응답 → 영역별 점수 산출
                      memoryScore + otherScore + adlScore 산출 (각 10점 만점, 백엔드 저장)
                      totalScore = 셋의 합 (30점 만점, 프론트 getter로 계산, 미저장)
                                ↓
                         ┌──────┴──────┐
                         ↓             ↓
                       0~5점          6~30점
                   주의(Borderline)  위험(HighRisk)
                         └──────┬──────┘
                                ↓
                             결과 화면 (+ 맞춤 솔루션, 주의/위험 모두 제공)
                                ↓
                    마이페이지 (검사 이력 확인)
```

# 2. 사이트맵

## 2.1 사용자(user) 

```text
/
├── /login
├── /register
├── /surveys              KDSQ-P(1차) 5문항
├── /surveys/detail       KDSQ-C(2차) 15문항
├── /results              검사 결과 (위험도 / 영역별 점수 / 솔루션 안내)
└── /mypage               회원정보(조회 전용) / 검사 이력
```

## 2.2 관리자(Admin) — Spring MVC + Thymeleaf

```text
/admin/login
/admin/dashboard              대시보드 (종합점수 추이 + 검사건수 추이 등)
/admin/members                회원 목록 (검색)
/admin/members/{id}/edit      회원 수정 (가입일 표기, 읽기전용)
/admin/members/{id}           회원 상세 + 검사 이력 (건수 표기, P/C 한 줄)
/admin/exams                  검사 결과 목록 (검사종류 필터 최상단, 검색창, 위험도 체크박스)
/admin/exams/{id}             검사 상세 결과 (읽기 전용, 회원명→상세 연결)
```

### 5.1.4 화면 상태 목록

| 상태  | 표시 내용  | 트리거     |
| ------ | --------- | ----------- |
| **초기 상태** | 이메일/비밀번호 입력 폼 및 로그인 버튼 표시   | 로그인 화면 진입           |
| **입력 중**  | 사용자가 입력한 이메일/비밀번호 표시          | 각 입력 필드에 값 입력       |
| **입력칸 공백**  | "이메일과 비밀번호를 입력해주세요." 메시지 표시   | 필수값 누락 (제출 차단)       |
| **입력 오류** | "올바른 이메일 형식이 아닙니다." 메시지 표시   | 이메일 형식 오류 (제출 차단)    |
| **로그인 진행 중** | 버튼 비활성화 + CircularProgress       | 로그인 버튼 클릭           |
| **로그인 성공**  | 로그인 처리 후 검사 화면(/surveys)으로 이동         | 로그인 API 성공          |
| **로그인 인증 실패-401**  | "이메일 또는 비밀번호를 확인해주세요." 메시지 표시   | 이메일 또는 비밀번호 불일치     |
| **탈퇴 회원-403**  | "이용할 수 없는 계정입니다." 메시지 표시   | 이메일 또는 비밀번호 불일치     |
| **네트워크 오류-5xx** | "일시적인 오류입니다. 잠시 후 다시 시도해주세요." 메시지 표시 | 서버 연결 실패            |
| **회원가입 이동** | 회원가입 화면(/register)으로 이동                | "회원가입하기" 클릭         |

> 보안상 "존재하지 않는 이메일"과 "비밀번호 불일치"를 구분해서 노출하지 않는다.

### 5.1.5 사용자 인터랙션 흐름

```
[authStore.isAuthenticated 확인]
   → [false] → [/login]
               ↓
         [이메일/비밀번호 입력]
           → [입력값 상태 업데이트]
           → [로그인 버튼 클릭] → loading = true
                 → [POST /api/auth/login]
                    → [200] → [토큰 저장(authStore)-로그인 처리 + /surveys 이동]
                    → [401] → [error: "이메일 또는 비밀번호를 확인해주세요."]
                    → [5xx] → [error: "일시적인 오류입니다. 잠시 후 다시 시도해주세요."]
   → [true] → [/surveys]

[회원가입하기 클릭]
    → [회원가입 화면으로 이동]
```

adlScore = Q11 + Q12 + Q13 + Q14 + Q15

| `submitting`      | `boolean`             | 검사 결과 제출 중 여부                         |
| `memoryScore`     | `number`              | 1~5번 문항의 기억력 영역 점수                    |
| `otherScore`      | `number`              | 6~10번 문항의 기타 인지기능 영역 점수               |
| `adlScore`        | `number`              | 11~15번 문항의 일상생활수행능력 영역 점수             |
| `totalScore`      | `number`              | `memoryScore + otherScore + adlScore` |

> **데이터 저장 정책**: 문항별 개별 응답(answers)은 저장하지 않고, `memoryScore` / `otherScore` / `adlScore` / `totalScore` 만 `ExamResult`에 저장한다. 이 점수를 기반으로 영역별 통계(Admin 대시보드)를 제공한다

| **검사 이력 있음**    | 검사 결과 목록 및 추이 그래프 표시                      | 검사 이력 데이터 존재                |
| **결과 유형 표시**    | 정상 / 주의 / 고위험군                                 | 검사 결과 데이터 로딩 완료             |
| **회원정보 조회 실패**  | 회원정보 조회 실패 메시지 표시                         | `GET /api/members/me` 실패    |
| **검사 이력 조회 실패** | 검사 이력 조회 실패 메시지 표시                        | `GET /api/exams/history` 실패 |
| **네트워크 오류**     | "네트워크 오류가 발생했습니다. 잠시 후 다시 시도해주세요." 메시지 표시 | 서버 연결 실패                    |
| **로그아웃**        | 로그아웃 처리 후 로그인 화면 이동                       | 로그아웃 클릭                     |

### 5.6.5 상태 및 데이터 정의 

| 상태 변수         | 타입             | 설명                |

### 5.6.6 검사 이력 표시 기준

| 항목     | 내용               |
| ------ | ---------------- |
| **날짜** | 검사 완료일           |
| **검사** | KDSQ-P 또는 KDSQ-C |
| **총점** | 해당 검사 총점         |
| **결과** | 검사 점수에 따른 결과 유형  |

**결과 유형**

| 검사     |   점수 | 표시 결과       |
| ------ | ---: | ----------- |
| KDSQ-P |  0~3 | 정상          |
| KDSQ-P | 4~10 | 2차 진행       |
| KDSQ-C |  0~5 | 주의          |
| KDSQ-C | 6~30 | 고위험군      |

### 5.6.7 표시 규칙

| 원본 값 | 화면 표기 |
| :--- | :--- |
| `gender: MALE / FEMALE` | 남성 / 여성 |
| `birthYear: 1960` | 1960 (만 66세) — 현재연도 − 출생년도 |
| `examType: KDSQ_P / KDSQ_C` | KDSQ-P / KDSQ-C |
| `riskLevel: Normal` | `정상` Chip |
| `riskLevel: Borderline` | `주의` Chip |
| `riskLevel: HighRisk` | `위험` Chip |
| `createdAt` | `YYYY-MM-DD` (시각 생략) |

### 5.6.8 사용자 인터랙션 흐름

```text
[마이페이지 클릭]
   ↓
[ProtectedRoute 통과 확인 (토큰 유무)]
   ↓
[MyPage 마운트] → loading = true
   ↓
[GET /api/members/me]        ─┐
[GET /api/exams/history]     ─┴─ 병렬 호출 (Promise.all)
   → [두 요청 모두 성공]
          → [calcTotalScore()로 이력별 총점 합산 (서버는 영역 점수만 반환)]
                 ↓
         [examHistory.length === 0 ?]
              → [Yes] → [ProfileCard + 빈 상태 안내 (그래프 미렌더)]
              → [No]  → [ProfileCard + ExamHistoryTable + ExamTrendChart]

   → [401] → [토큰 만료] → [3.4 재발급 플로우]

   → [그 외 오류] → [Alert + 다시 시도 버튼]
```

**토큰 만료 / 재발급**

```text
[API 응답 401 수신 (axios 응답 인터셉터)]
   ↓
[리프레시 토큰 보유?]
   │
   ├── [Yes] → [POST /api/auth/reissue]
   │            ├── [성공] → [새 액세스 토큰 저장] → [실패했던 요청 1회 재시도]
   │            └── [실패] → [authStore.logout()] → [/login ("다시 로그인해주세요.")]
   │
   └── [No]  → [authStore.logout()] → [/login]
```

**로그아웃**

```text
[로그아웃 클릭]
   ↓
[POST /api/auth/logout   (서버 리프레시 토큰 폐기)]
   ↓
[authStore.logout()      (액세스·리프레시 토큰 및 memberStore 초기화)]
   ↓
[/login 으로 replace 이동 (뒤로가기로 복귀 불가)]
```

> 액세스 토큰은 stateless이므로 클라이언트 삭제가 실질적인 로그아웃이며,
> 서버 호출은 리프레시 토큰 재사용을 막기 위한 것이다. API 실패 시에도 클라이언트 상태는 반드시 초기화한다.

# 8. 상태 관리 전략

## 8.1 로컬 상태 vs 전역 상태 구분

| 상태 | 범위 | 위치 | 사유 |
| :--- | :--- | :--- | :--- |
| `email`, `password` (로그인 입력값) | 로컬 | `LoginForm` | 해당 폼 밖에서 쓰이지 않음 |
| 회원가입 6개 입력값 | 로컬 | `RegisterForm` | 제출 후 폐기 |
| 폼 유효성 에러 | 로컬 | 각 Form | 폼 생명주기와 동일 |
| `loading`, `submitting` | 로컬 | 각 Page | 화면 단위 |
| **토큰 / 인증 여부** | **전역** | `authStore` | Header·ProtectedRoute·axios 인터셉터가 공유 |
| **회원정보 / 검사이력** | **전역** | `memberStore` | 마이페이지 재진입 시 재사용, 결과 화면과 공유 가능 |

## 8.2 authStore (Zustand)

```text
authStore
├── accessToken          string | null
├── refreshToken         string | null
├── isAuthenticated      boolean
├── setTokens(access, refresh)
├── setAccessToken(access)      // 재발급 시
└── logout()                    // 토큰 제거 + memberStore.reset()
```

```javascript
// store/authStore.js
import { create } from 'zustand';
import { persist } from 'zustand/middleware';
import { useMemberStore } from './memberStore';

export const useAuthStore = create(
  persist(
    (set) => ({
      accessToken: null,
      refreshToken: null,
      isAuthenticated: false,

      setTokens: (accessToken, refreshToken) =>
        set({ accessToken, refreshToken, isAuthenticated: true }),

      setAccessToken: (accessToken) => set({ accessToken }),

      logout: () => {
        useMemberStore.getState().reset();
        set({ accessToken: null, refreshToken: null, isAuthenticated: false });
      },
    }),
    { name: 'kdsq-auth' }
  )
);
```

## 8.3 memberStore (Zustand)

```text
memberStore
├── member          { name, email, gender, birthYear } | null
├── examHistory     ExamResult[]   ← 서버 응답 원본 (영역 점수만, 총점 없음)
├── loading         boolean
├── error           string | null
├── fetchMyPage()   member·examHistory 병렬 조회
└── reset()         로그아웃 시 초기화
```

```javascript
// store/memberStore.js
import { create } from 'zustand';
import { memberApi } from '../api/memberApi';

export const useMemberStore = create((set) => ({
  member: null,
  examHistory: [],
  loading: false,
  error: null,

  fetchMyPage: async () => {
    set({ loading: true, error: null });
    try {
      const [member, examHistory] = await Promise.all([
        memberApi.getMe(),
        memberApi.getExamHistory(),
      ]);
      set({ member, examHistory, loading: false });
    } catch (e) {
      set({ error: '정보를 불러오지 못했습니다.', loading: false });
    }
  },

  reset: () => set({ member: null, examHistory: [], loading: false, error: null }),
}));
```
