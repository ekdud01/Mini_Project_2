# KDSQ 인지선별검사 플랫폼 화면 설계서 (v4)

## 0. 개정 이력

| 버전 | 주요 변경 |
| --- | --- |
| v1 | 최초 작성 |
| v2 | 컷오프 임시 변경, 회원정보 수정 불가, 학력 제외, Admin(Thymeleaf) 신설 |
| v3 | 컷오프 도메인 기준 원복, 주의 등급 솔루션 버튼, firstScore 추가, totalScore 프론트 계산, 탈퇴 기능 추가 |
| **v4** | **1인 개발 현실성 반영** — 탈퇴 승인 워크플로우(ADM-07) 제거하고 즉시삭제+프론트 이중확인으로 단순화, 회차 그룹핑(세션ID/윈도우함수) 제거하고 flat list + 상태라벨로 단순화, 미완료 이탈 시 삭제 로직 제거(그냥 유지), Admin 대시보드 연령비교 제외, ADM-06 완전 읽기전용 확정 |

## 1. 문서 개요

### 1.1 시스템 구성

- **User 프론트엔드**: React SPA
- **Admin 페이지**: Spring MVC + Thymeleaf 서버사이드 렌더링 (React 미사용, 별도 아키텍처, **1인 개발**)
- **DB**: 병원 로컬 DB. 개발사는 데이터 접근 없이 유지보수만 수행
- **권한 3그룹**: 개인(User) / 병원관계자(Admin) / 개발자(유지보수 전용, 데이터 접근 없음)
- **로그인 필수**, **회원정보 수정은 User 불가 / Admin 가능**, **회원 탈퇴는 즉시 삭제(1단계)**

> v4의 설계 원칙: **백엔드 로직·스키마 변경을 최소화**하고, 가능한 부분은 프론트엔드/뷰 렌더링 단에서 처리한다. 1인 개발 환경을 고려한 현실적 범위 축소를 최우선한다.

### 1.2 핵심 흐름 (컷오프: 도메인설계서 기준 확정)

```text
회원가입 (로그인 필수)
   ↓
로그인
   ↓
검사 메인
   ↓
KDSQ-P (1차) 5문항 검사
   ↓
firstScore 산출 (10점 만점)
   ├── 0~3점  → 정상 → 결과 화면 → 종료
   │
   └── 4~10점 → KDSQ-C (2차) 상세검사로 전환
                    ↓
              memoryScore + otherScore + adlScore 산출 (각 10점 만점, 백엔드 저장)
              totalScore = 셋의 합 (30점 만점, 프론트 getter로 계산, 미저장)
                    ↓
             ┌──────┴──────┐
             ↓             ↓
          0~5점           6~30점
          주의(Borderline)  위험(HighRisk)
             └──────┬──────┘
                    ↓
                 결과 화면 (+ 맞춤 솔루션, 주의/위험 모두 제공)
                    ↓
           마이페이지 (검사 이력 / 회원 탈퇴)
```

## 2. 사이트맵

### 2.1 사용자(User)

```text
/
├── /login
├── /register
├── /surveys              KDSQ-P(1차) 5문항
├── /surveys/detail       KDSQ-C(2차) 15문항
├── /results              검사 결과 (위험도 / 영역별 점수 / 솔루션 안내)
└── /mypage               회원정보(조회 전용) / 검사 이력 / 회원 탈퇴(즉시삭제)
```

### 2.2 관리자(Admin) — Spring MVC + Thymeleaf

```text
/admin/login
/admin/dashboard              대시보드 (통계 요약, 연령비교 제외)
/admin/members                회원 목록 (검색)
/admin/members/{id}/edit      회원 수정
/admin/members/{id}           회원 상세 + 검사 이력 (flat list)
/admin/exams                  검사 결과 목록 (위험도 체크박스 필터)
/admin/exams/{id}             검사 상세 결과 (읽기 전용)
```

> v3 대비 `/admin/withdrawal-requests`(ADM-07) **삭제**.

## 7. SCR-03 검사 메인 화면 (KDSQ-P, 1차)

### 7.1 제출 처리 (컷오프 도메인 기준)

```text
KDSQ-P 제출
      ↓
firstScore 계산 (10점 만점)
      ↓
┌───────────────┐
│ 0 ~ 3점       │ → 정상 판정 → 결과 화면 → 종료
└───────────────┘

┌───────────────┐
│ 4 ~ 10점      │ → KDSQ-C(2차) 상세검사 안내
└───────────────┘
```

### 7.2 API

```text
GET  /api/surveys/p
POST /api/exams/p     ← firstScore 저장. 재시작 시 별도 삭제/병합 로직 없이 그냥 새 레코드 생성
```

> ⚠️ **v4 단순화**: 이전에 검토했던 "미완료 KDSQ-C 상태에서 재시작 시 이전 P 삭제" 로직은 **적용하지 않는다.** 그냥 새 KDSQ-P 레코드를 추가한다. 미완료 이력은 화면(ADM-04)에서 라벨로만 구분한다.

## 8. SCR-04 KDSQ-C 상세검사 화면 (2차)

### 8.1 영역 구분 및 점수 필드

| 영역 | 문항 | 점수 필드 (백엔드 저장) |
| --- | --- | --- |
| 기억력 (KDSQ-M) | 1~5 | `memoryScore` (10점 만점) |
| 기타 인지기능 (KDSQ-O) | 6~10 | `otherScore` (10점 만점) |
| 일상생활수행능력 (KDSQ-A) | 11~15 | `adlScore` (10점 만점) |

> **`totalScore`는 백엔드 저장 필드가 아니다.** 프론트엔드에서 getter로 계산한다 (아래 8.2 참고). 문항별 개별 응답은 저장하지 않는다.

### 8.2 프론트 계산 로직 (참고용, 구현은 추후)

```text
ExamResult 모델
├── firstScore
├── memoryScore
├── otherScore
├── adlScore
├── riskLevel
├── createdAt
└── totalScore  ← getter: memoryScore + otherScore + adlScore (저장 안 함)
```

### 8.3 API

```text
GET  /api/surveys/c
POST /api/exams/c     ← memoryScore/otherScore/adlScore, riskLevel 저장
```

### 8.4 제출 후 처리 (컷오프 도메인 기준)

```text
15문항 제출
     ↓
영역별 점수 계산
     ↓
totalScore = memoryScore + otherScore + adlScore (프론트 계산, 표시 전용)
     ↓
위험도 판정
  ├── 0~5점  → 주의(Borderline)
  └── 6~30점 → 위험(HighRisk)
     ↓
결과 화면
```

### 10.2 회원 탈퇴 흐름 (v4 단순화 — 즉시삭제 + 프론트 이중확인)

```text
[회원 탈퇴] 클릭
      ↓
확인 모달 노출
  "탈퇴 시 계정과 모든 검사 이력이 영구 삭제되며 복구할 수 없습니다.
   계속하려면 '탈퇴'를 입력하세요."
  [입력창: ________]   ← "탈퇴" 정확히 입력해야 버튼 활성화 (프론트 로직만, 백엔드 변경 없음)
  [취소]  [탈퇴하기]  (미입력 시 비활성)
      ↓ (탈퇴하기)
DELETE /api/members/me   ← Member + ExamResult 즉시 hard delete
      ↓
authStore.logout() 실행 (토큰 제거)
      ↓
로그인 화면으로 리다이렉트 + "탈퇴가 완료되었습니다." 안내
```

## 23. 핵심 설계 요약 (v4)

```text
회원(로그인 필수, 정보수정 불가, 탈퇴는 즉시삭제)
 ↓
KDSQ-P(1차) → firstScore 저장 (재시작 시 삭제/병합 없이 그냥 새 레코드)
 ↓
0~3점 → 정상, 종료
4~10점
       ↓
     KDSQ-C(2차) → memoryScore/otherScore/adlScore 저장
       ↓
     totalScore = 3영역 합산 (프론트 getter, 미저장)
       ↓
     0~5점  → 주의  → 솔루션 안내
     6~30점 → 위험  → 솔루션 안내
                    ↓
              마이페이지 (검사 이력, flat list / 회원 탈퇴)

[별도] 병원관계자(Admin, Thymeleaf, 1인 개발)
 ↓
대시보드(통계, 연령비교 제외) / 회원관리(조회+수정+삭제) / 검사결과관리(조회 전용)
```

**핵심 데이터 (ExamResult)**

```text
id, memberId, examType,
firstScore,          // KDSQ-P 점수, 저장
memoryScore,         // 저장
otherScore,          // 저장
adlScore,            // 저장
riskLevel,
createdAt
// totalScore: 저장 안 함, 프론트 getter로 계산
// sessionId: 도입하지 않음, flat list + 뷰단 라벨로 대체
```

**핵심 비즈니스 규칙 (v4 최종)**

```text
KDSQ-P 0~3점  → 정상
KDSQ-P 4~10점 → KDSQ-C 추가 검사

KDSQ-C 0~5점  → 주의(Borderline)
KDSQ-C 6~30점 → 위험(HighRisk)
```
