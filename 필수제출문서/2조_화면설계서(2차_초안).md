# KDSQ 인지선별검사 플랫폼 화면 설계서 (v3)

## 0. 개정 이력

| 버전 | 주요 변경 |
| --- | --- |
| v1 | 최초 작성 |
| v2 | 컷오프 임시 변경, 회원정보 수정 불가, 학력 제외, Admin(Thymeleaf) 신설 |
| **v3** | **컷오프를 도메인설계서 기준으로 원복**, 주의 등급 솔루션 버튼 추가, `firstScore` 필드 추가, `totalScore` 프론트 계산 필드로 전환, 회원 탈퇴 기능 추가, Admin 화면을 도메인 객체 기준으로 재정비 |

---

## 1. 문서 개요

### 1.1 시스템 구성

- **사용자(User) 프론트엔드**: React SPA
- **관리자(Admin) 페이지**: Spring MVC + Thymeleaf 서버사이드 렌더링 (React 미사용, 별도 아키텍처)
- **DB**: 병원 로컬 DB. 개발사는 데이터 접근 없이 유지보수만 수행
- **권한 3그룹**: 개인(User) / 병원관계자(Admin) / 개발자(유지보수 전용, 데이터 접근 없음)
- **로그인 필수**, **회원정보 수정 불가**(가입 후 조회만 가능), **회원 탈퇴 가능**

### 1.2 핵심 흐름 (컷오프: 도메인설계서 기준으로 확정)

```text
회원가입 (로그인 필수)
   ↓
로그인
   ↓
검사 메인
   ↓
KDSQ-P (1차) 5문항 검사
   ↓
firstScore 산출
   ├── 0~3점  → 정상 → 결과 화면 → 종료
   │
   └── 4~10점 → KDSQ-C (2차) 상세검사로 전환
                    ↓
              memoryScore + otherScore + adlScore 산출
              (totalScore는 프론트에서 세 값을 합산해 계산)
                    ↓
             ┌──────┴──────┐
             ↓             ↓
          0~5점           6~30점
          주의(Borderline)  위험(HighRisk)
             └──────┬──────┘
                    ↓
                 결과 화면 (+맞춤 솔루션, 주의/위험 모두 제공)
                    ↓
           마이페이지 (검사 이력 / 회원 탈퇴)
```

> ✅ v2에서 임시로 바꿨던 "4점 이하 종료 / 6점 이하 주의" 기준은 **도메인설계서(BR-001, BR-002)에 맞춰 원래 기준(0~3 / 4~10, 0~5 / 6~30)으로 되돌렸습니다.**

## 8. SCR-04 KDSQ-C 상세검사 화면 (2차)

### 8.1 영역 구분 및 점수 필드

| 영역 | 문항 | 점수 필드 (백엔드 저장) |
| --- | --- | --- |
| 기억력 (KDSQ-M) | 1~5 | `memoryScore` |
| 기타 인지기능 (KDSQ-O) | 6~10 | `otherScore` |
| 일상생활수행능력 (KDSQ-A) | 11~15 | `adlScore` |

> **`totalScore`는 백엔드에 저장되는 필드가 아니다.** 백엔드는 `memoryScore` / `otherScore` / `adlScore` 3개 영역별 점수만 저장하며, **프론트엔드에서 이 세 값을 합산하는 getter로 총점을 계산**해 화면에 표시한다.

```js
// 프론트 예시: ExamResult 모델의 getter
class ExamResult {
  constructor({ firstScore, memoryScore, otherScore, adlScore, riskLevel, createdAt }) {
    this.firstScore = firstScore;
    this.memoryScore = memoryScore;
    this.otherScore = otherScore;
    this.adlScore = adlScore;
    this.riskLevel = riskLevel;
    this.createdAt = createdAt;
  }

  // 저장 필드가 아닌 계산 전용 getter
  get totalScore() {
    return this.memoryScore + this.otherScore + this.adlScore;
  }
}
```

### 8.2 API

```text
GET  /api/surveys/c
POST /api/exams/c     ← memoryScore/otherScore/adlScore, riskLevel 저장 (totalScore 미저장)
```

### 8.3 제출 후 처리 (컷오프 도메인 기준으로 원복)

```text
15문항 제출
     ↓
영역별 점수 계산 (memoryScore / otherScore / adlScore)
     ↓
totalScore = memoryScore + otherScore + adlScore  (프론트 getter 계산, 화면 표시용)
     ↓
위험도 판정
  ├── 0~5점  → 주의 (Borderline)
  └── 6~30점 → 위험 (HighRisk)
     ↓
결과 화면
(문항별 응답은 저장하지 않음)
```

```text
│           │   ADL(adlScore)         2.5점                  │
│           │                                               │
│           │  최근 위험(HighRisk) 검사 목록 (바로가기)        │
└───────────┴───────────────────────────────────────────────┘
```

### 11.2 Model 속성

```text
totalActiveMembers      // status = ACTIVE
totalWithdrawnMembers   // status = WITHDRAWN
totalExams

avgFirstScore           // KDSQ-P 평균

avgMemoryScore

```

> 대시보드의 `totalScore` 평균은 **백엔드 Service에서 세 영역 점수를 합산 후 집계**한다. (User 프론트의 getter 계산과는 별개로, Admin 통계는 서버에서 계산 — SQL 집계 함수 활용 가능)

## 23. 핵심 설계 요약 (v3)

```text
회원(로그인 필수, 정보수정 불가, 탈퇴 가능)
 ↓
KDSQ-P(1차) → firstScore 저장
 ↓
0~3점 → 정상, 종료
4~10점
       ↓
     KDSQ-C(2차) → memoryScore/otherScore/adlScore 저장
       ↓
     totalScore = 3영역 합산 (프론트 getter 계산, 미저장)
       ↓
     0~5점  → 주의  → 솔루션 안내
     6~30점 → 위험  → 솔루션 안내
                    ↓
              마이페이지 (검사 이력 / 회원 탈퇴)

[별도] 병원관계자(Admin, Thymeleaf)
 ↓
대시보드(통계, totalScore 서버 집계) / 회원관리(상태 필터) / 검사결과관리(+솔루션 조회)
```

**핵심 데이터 (ExamResult, 도메인설계서 기준)**

```text
id, memberId, examType,
firstScore,          // KDSQ-P 점수, 저장
memoryScore,         // 저장
otherScore,          // 저장
adlScore,            // 저장
riskLevel,
createdAt
// totalScore: 저장 안 함, 프론트 getter로 memoryScore+otherScore+adlScore 계산
```

**핵심 비즈니스 규칙 (도메인설계서 기준 확정)**

```text
KDSQ-P 0~3점  → 정상
KDSQ-P 4~10점 → KDSQ-C 추가 검사

KDSQ-C 0~5점  → 주의(Borderline)
KDSQ-C 6~30점 → 위험(HighRisk)

주의/위험 판정 시 맞춤 솔루션 제공 (양쪽 모두)
문항별 응답 미저장, 영역별 score만 ExamResult에 저장
회원정보 → 가입 후 수정 불가, 탈퇴는 가능 (ACTIVE → WITHDRAWN)
```
