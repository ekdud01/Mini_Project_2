## 1. 문서 개요

### 1.1 시스템 구성

- **User 프론트엔드**: React SPA
- **Admin 페이지**: Spring MVC + Thymeleaf 서버사이드 렌더링 (React 미사용, 별도 아키텍처, **1인 개발**)
- **DB**: 병원 로컬 DB. 개발사는 데이터 접근 없이 유지보수만 수행
- **권한 3그룹**: 개인(User) / 병원관계자(Admin) / 개발자(유지보수 전용, 데이터 접근 없음)
- **로그인 필수**, **회원정보 수정은 User 불가 / Admin 가능**, **회원 탈퇴는 즉시 삭제(1단계)**

> 설계 원칙(v4부터 유지): 백엔드 로직·스키마 변경을 최소화하고, 가능한 부분은 프론트엔드/뷰 렌더링 단에서 처리한다. 1인 개발 환경을 고려한 현실적 범위를 우선한다.

### 1.2 핵심 흐름 (컷오프: 도메인설계서 기준 확정)

```text
회원가입 (로그인 필수)
   ↓
로그인
   ↓
검사 메인
   ↓
KDSQ-P (1차) 5문항 검사
   ↓
firstScore 산출 (10점 만점)
   ├── 0~3점  → 정상 → 결과 화면 → 종료
   │
   └── 4~10점 → KDSQ-C (2차) 상세검사로 전환
                    ↓
              memoryScore + otherScore + adlScore 산출 (각 10점 만점, 백엔드 저장)
              totalScore = 셋의 합 (30점 만점, 프론트 getter로 계산, 미저장)
                    ↓
             ┌──────┴──────┐
             ↓             ↓
          0~5점           6~30점
          주의(Borderline)  위험(HighRisk)
             └──────┬──────┘
                    ↓
                 결과 화면 (+ 맞춤 솔루션, 주의/위험 모두 제공)
                    ↓
           마이페이지 (검사 이력 / 회원 탈퇴)
```

## 2. 사이트맵

### 2.1 사용자(User)

```text
/
├── /login
├── /register
├── /surveys              KDSQ-P(1차) 5문항
├── /surveys/detail       KDSQ-C(2차) 15문항
├── /results              검사 결과 (위험도 / 영역별 점수 / 솔루션 안내)
└── /mypage               회원정보(조회 전용) / 검사 이력 / 회원 탈퇴(즉시삭제)
```

### 2.2 관리자(Admin) — Spring MVC + Thymeleaf

```text
/admin/login
/admin/dashboard              대시보드 (종합점수 추이 + 검사건수 추이 등)
/admin/members                회원 목록 (검색)
/admin/members/{id}/edit      회원 수정 (가입일 표기, 읽기전용)
/admin/members/{id}           회원 상세 + 검사 이력 (건수 표기, P/C 한 줄)
/admin/exams                  검사 결과 목록 (검사종류 필터 최상단, 검색창, 위험도 체크박스)
/admin/exams/{id}             검사 상세 결과 (읽기 전용, 회원명→상세 연결)
/admin/exams/export           Raw 데이터 CSV 추출 (신규)
```

> - P/C 그룹핑: v4와 동일하게 **DB 쿼리는 단순 정렬(`ORDER BY created_at`) 그대로**, Java 리스트를 한 번 순회하며 그룹핑 (스키마/쿼리 변경 없음)

```text
┌───────────────────────────────────────────────────────────┐
│  검사 결과 관리                                              │
│  검사종류 [전체 ▼]   위험도 ☑정상 ☑주의 ☑고위험군            │
│  [검색: 이름____]  [날짜: 2026-09-01 ~ 2026-09-22]  [검색]   │
│                                          [원본 데이터 추출]   │
├───────────────────────────────────────────────────────────┤
│ 날짜        회원    KDSQ-P(점수/판정)   KDSQ-C(점수/판정)  위험도  [작업]│
│ 2026-09-22  홍길동  3점/정상            —                 정상   [상세보기]│
│ 2026-09-21  김영희  8점/2차대상         9점/고위험군       고위험군[상세보기]│

```

**반영 사항**
- 검사종류 필터를 맨 앞으로 이동
- 이름/날짜 검색창 신규 추가
- P/C 한 줄 표기: 전체 회원 대상이므로 `Map<회원ID, 대기중인 KDSQ-P>` 자료구조로 순회하며 그룹핑 (SQL 변경 없음, 자바 로직만 추가)
- 위험도 체크박스: 정상/주의/고위험군 3개 고정 (v4 유지)
- **[원본 데이터 추출]** 버튼 신규 추가

### 14.2 Raw 데이터 추출 (신규)

**추출 기준(확정)**
- 대상: 검사결과 목록(ADM-05) 기준, **현재 적용된 필터(검사종류/위험도/이름/날짜) 그대로** 적용
- 포함 필드: 회원명, 이메일, 검사종류, firstScore, memoryScore, otherScore, adlScore, totalScore(서버계산), riskLevel, 검사일시
- 형식: **CSV** (Excel 라이브러리 불필요, Java 기본 기능만으로 스트리밍 가능)
- 문항별 개별 응답은 원래 저장하지 않으므로 추출 대상에서 제외 (기존 정책 유지)

```text

   ↓
현재 목록과 동일한 필터 조건으로 전체(페이징 없이) 재조회

CSV 스트림 생성 (java.io.Writer 기반, 외부 의존성 불필요)
   ↓
Content-Disposition: attachment 로 브라우저 다운로드
```

## 23. 핵심 설계 요약 (v5)

```text
회원(로그인 필수, 정보수정 불가, 탈퇴는 즉시삭제)
 ↓
KDSQ-P(1차) → firstScore 저장
 ↓
0~3점 → 정상, 종료
4~10점
       ↓
     KDSQ-C(2차) → memoryScore/otherScore/adlScore 저장
       ↓
     totalScore = 3영역 합산 (프론트 getter, 미저장)
       ↓
     0~5점  → 주의  → 솔루션 안내
     6~30점 → 위험  → 솔루션 안내
                    ↓
              마이페이지 (검사 이력 / 회원 탈퇴)

[별도] 병원관계자(Admin, Thymeleaf, 1인 개발)
 ↓
대시보드(통계 + 월별 종합점수·건수 이중 추이)
회원관리(조회+수정[가입일표기]+삭제, 검사이력 건수+P/C한줄)
검사결과관리(검사종류 필터 최상단 + 검색 + P/C한줄 + Raw CSV 추출)
   ↔ 회원상세 ↔ 검사상세 양방향 연동
```

**핵심 데이터 (ExamResult, 변경 없음)**

```text
id, memberId, examType,
firstScore, memoryScore, otherScore, adlScore,
riskLevel, createdAt
// totalScore: 저장 안 함, 프론트 getter로 계산
// 세션ID 도입하지 않음 — Java 리스트 순회로 P/C 그룹핑 (ExamHistoryGrouper)
```

**v5 신규/변경 요소 요약**

```text
- 로그인 안내 문구: 관리자 계정 사전등록 안내로 변경
- 대시보드: 월별 종합점수 추이 + 월별 검사건수 추이 병행
- 회원수정: 가입일 읽기전용 표기
- 회원상세: 검사이력 건수 표기, P/C 한 줄, [상세보기] 버튼명
- 검사결과목록: 검사종류 필터 최상단, 이름/날짜 검색 추가, P/C 한 줄
- 검사상세: 회원명 클릭 → 회원상세로 연결
- Raw 데이터 CSV 추출: 검사결과 목록 기준, 현재 필터 반영, CSV 형식
```
